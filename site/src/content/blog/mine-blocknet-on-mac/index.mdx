## Can you mine Blocknet on a Mac?

<Answer>
Download seine, extract it, enter your Blocknet address, and confirm accepted shares on bntpool.com. Start with automatic settings; tuning advice comes after setup.
</Answer>

## Step 1: download the right build

In Apple menu → About This Mac, check the chip or processor. Choose `seine-macos-aarch64.tar.gz` for Apple Silicon, or `seine-macos-x86_64.tar.gz` for Intel in the [download section](/#download).

## Step 2: extract and launch

Open Terminal. These commands assume the archive is in your Downloads folder; use its actual location if different. On an Intel Mac, replace `seine-macos-aarch64.tar.gz` with `seine-macos-x86_64.tar.gz`. They extract seine into your home folder and launch it:

```sh
mkdir -p "$HOME/seine"
tar -xzf "$HOME/Downloads/seine-macos-aarch64.tar.gz" -C "$HOME/seine"
cd "$HOME/seine"
./seine
```

## Step 3: enter your wallet address

Paste your public Blocknet receiving address or registered `@name`, then press Enter to accept `stratum+tcp://bntpool.com:3333`. The [wallet guide](/blog/blocknet-wallet-for-mining/) shows where to find your address. Seine does not need your recovery phrase or spending keys. It assigns a pool worker name automatically.

## Step 4: check accepted shares

Look for a hashrate and an increasing **Accepted** counter in the [dashboard](/blog/seine-dashboard-explained/). An accepted share confirms the pool received your work; it does not mean a payout has happened. Press `q` or `Ctrl+C` to stop.

## If macOS blocks the first launch

The macOS build is ad-hoc signed. If macOS stops the first launch, open System Settings, go to Privacy & Security, and allow `seine`. You can also clear the download flag from Terminal and run it again:

```sh
xattr -d com.apple.quarantine ./seine
./seine
```

## Why do Apple Silicon Macs mine Blocknet well?

Blocknet's proof of work is [Argon2id](/blog/argon2id-proof-of-work-explained/) with 2 GiB of memory per hash. Each hash fills a 2 GiB block of memory, reading back earlier parts of it as it goes, so the speed of a mining thread depends mostly on how fast the chip can move data to and from memory. That is why each seine thread needs about 2 GB of RAM of its own.

Apple Silicon is built around unified memory, which [Apple describes](https://www.apple.com/newsroom/2020/11/apple-unleashes-m1/) as high-bandwidth, low-latency memory brought together into a single pool. That gives every mining thread plenty of bandwidth, which is exactly what a memory-hard hash needs. The result is a laptop that mines Blocknet in the same range as server processors.

## How fast does an M4 Max mine Blocknet?

<Answer>
A 48 GB MacBook Pro with the M4 Max chip mined Blocknet at 30.94 H/s with 16 threads on its CPU alone. At 14 threads with performance-core scheduling, the balanced setting seine runs by default on that machine, it mined at 29.26 H/s and left more memory free for other apps.
</Answer>

These results come from seine's validation sweep on a 48 GB M4 Max (12 performance cores and 4 efficiency cores) on 2026-07-10:

| Setting | Threads | Hashrate |
|---|---|---|
| Maximum throughput | 16, `auto` scheduling | 30.94 H/s |
| Balanced (seine's default ceiling on this Mac) | 14, `pcore-only` scheduling | 29.26 H/s |

## How many threads can your Mac run?

Every thread needs its own 2 GiB of memory, so memory sets the ceiling. Seine also leaves 5% (at most 1 GiB by default) of your Mac's memory free as headroom when it sizes itself. That gives these upper limits:

| Mac memory | Threads the memory can hold |
|---|---|
| 16 GB | up to 7 |
| 24 GB | up to 11 |
| 32 GB | up to 15 |
| 36 GB | up to 17 |
| 48 GB | up to 23 |
| 64 GB | up to 31 |

Two things bring the final number to the right fit for your Mac:

- **Free memory.** Seine counts the memory that is actually free when it starts, so apps you have open reduce the count a little. If memory gets tight while it runs, seine parks threads and releases their memory.
- **Cores.** By default on a Mac, seine uses all of the performance cores plus half of the efficiency cores. On the 12+4 core M4 Max, that is 14 threads, the balanced setting in the table above.

You don't need to work any of this out. Seine picks the thread count when it starts and keeps testing nearby counts while it mines.

## Why does seine mine on the CPU only on a Mac?

On Apple Silicon the CPU and the graphics cores share one pool of unified memory. Argon2id depends on memory bandwidth, so the CPU and the graphics cores would compete for the same bandwidth. In seine's testing on the M4 Max, CPU-only mining gave the highest hashrate, so seine selects it automatically on every Apple Silicon Mac. You get the fastest setup with no flags to set.

## How do you get the most from a Mac?

- **Let seine tune itself.** It compares thread counts and CPU kernels on real mining work, switches only after a confirmed gain, and remembers the result for the next start.
- **Keep the Mac awake.** macOS puts an idle Mac to sleep, which pauses mining. Start seine with the built-in `caffeinate` command to keep the Mac awake for as long as seine runs:

  ```sh
  caffeinate -i ./seine
  ```

- **Go for maximum throughput on a dedicated Mac.** If the Mac is doing nothing but mining, the setting that measured 30.94 H/s on the M4 Max uses all 16 cores and more memory than the balanced default:

  ```sh
  ./seine --backend cpu --threads 16 --cpu-affinity auto
  ```

For every option, see the [configuration guide](https://github.com/zpalmtree/seine/blob/master/docs/guides/configuration.md). The [main mining guide](/blog/how-to-mine-blocknet/) covers payouts and the other platforms.

<Note>
These results describe Blocknet's current Argon2id proof of work. Blocknet plans a network upgrade called Faraday around 2027-02-16 that is planned to change the proof of work, according to [blocknetcrypto.com](https://blocknetcrypto.com/#faraday). Seine checks for new releases when it starts and every 12 hours, so keep it up to date.
</Note>
