Blocknet을 받거나 채굴을 시작하려고 설정 지침을 보면 지갑, 노드, 채굴기라는 세 이름이 나옵니다. 한 앱이 여러 기능을 포함하더라도 각각 다른 일을 뜻합니다. 역할을 이해하면 알맞은 소프트웨어를 설치하고 개인 키를 적절한 곳에 보관하며 어떤 프로세스를 계속 실행해야 하는지 알 수 있습니다.

## 지갑, 노드, 채굴기의 차이는 무엇인가요?

<Answer>
Blocknet 지갑은 키를 관리하고 자신의 자금을 식별합니다. 노드는 블록체인을 따라가며 검증합니다. 채굴기는 작업 증명 계산을 수행합니다. 풀 채굴에서 seine는 채굴 노드 연결을 담당하는 풀에 연결합니다. 지갑은 결제를 관리하는 별도의 신뢰할 수 있는 컴퓨터에 그대로 둘 수 있습니다.
</Answer>

## 때로는 한 앱에 담긴 세 가지 역할

공식 Blocknet 소프트웨어는 노드와 지갑 기능을 결합하므로 지갑 가이드에도 코어 시작과 동기화 대기가 나옵니다. 명령줄 클라이언트는 코어를 관리하고 지갑 명령용 대화형 셸을 엽니다. seine는 별도의 채굴 앱입니다. 기본 모드는 풀에 연결하고 직접 모드는 사용자가 운영하는 노드에 연결합니다.

| 그림 속 역할 | 주요 작업 | 필요한 때 |
| --- | --- | --- |
| 1. 지갑 | 키 관리, 결제 찾기, 지출 승인 | 자신의 자금을 관리할 때 |
| 2. 노드 | 체인 추적과 검증, 블록체인 데이터 제공 | 공식 지갑 절차 또는 자체 직접 채굴 연결에 사용 |
| 3. 채굴기 | 채굴 작업으로부터 작업 증명 계산 | 채굴하기로 선택할 때 |

역할들이 한 컴퓨터를 공유할 수 있지만 필수는 아닙니다. 한 구성 요소를 설치했다고 나머지가 모두 실행되는 것은 아닙니다. 원하는 작업부터 정한 뒤 이를 지원하는 구성을 선택하세요.

## 지갑에는 실제로 무엇이 들어 있나요?

지갑은 자금을 찾고 지출하는 데 필요한 키와 로컬 정보를 보관합니다. 코인은 블록체인에서 기록되므로 지갑 파일을 복사해도 다른 잔액이 생기지 않습니다. 같은 전체 지갑의 두 복사본이 동일한 자금에 접근할 수 있으므로 백업도 사용 중인 지갑만큼 주의해서 보호해야 합니다. 공개 수신 주소는 다른 사람이 어디로 결제할 수 있는지 알려 줍니다.

새 지갑은 [지갑 설정 가이드](/ko/blog/blocknet-wallet-for-mining/)에 따라 만들고 [백업 및 복구 가이드](/ko/blog/blocknet-wallet-backup-restore/)로 보호된 백업을 보관하세요. 풀 연결에는 수신 주소 또는 지원되는 이름이 필요하며, 복구 시드나 지갑 파일, 지갑 비밀번호는 필요하지 않습니다. 여러 채굴 컴퓨터에 공개 지급 대상을 설정하면서 전체 지갑은 자금을 관리하는 컴퓨터에 둘 수 있습니다.

## 노드는 지갑을 위해 무엇을 하나요?

노드는 피어에 연결해 블록체인을 따라가고 받아들이는 체인을 검증합니다. 이후 지갑이 체인 데이터를 스캔해 자신의 출력을 식별합니다. 서로 관련은 있지만 별개의 진행 상황입니다. 노드가 아직 블록을 다운로드 중일 수도 있고, 노드는 최신 상태인데 지갑은 계속 스캔 중일 수도 있습니다. 따라서 동기화 도중 보이는 초기 잔액은 불완전할 수 있습니다.

[노드 가이드](/ko/blog/run-blocknet-node/)는 공식 코어 시작과 연결 확인을 설명합니다. [지갑 동기화 가이드](/ko/blog/blocknet-wallet-not-syncing/)는 어떤 진행 지표를 봐야 하는지 설명합니다. 노드를 실행하는 것만으로 채굴 보상을 받지는 않습니다. 코어에 채굴 기능이 포함될 수 있지만 체인을 따라가는 일과 실제 채굴 작업은 별개의 동작입니다. 컴퓨터를 채굴기로 보기 전에 채굴 프로세스가 실제로 작업 중인지 확인하세요.

## seine와 풀은 각각 무엇을 하나요?

seine는 채굴 작업을 받아 활성화된 하드웨어로 작업 증명을 반복 계산합니다. 풀 모드에서는 요건을 충족하는 셰어를 풀로 보냅니다. 풀은 제출 결과를 확인하고 상위 노드와 통신하며 해결한 블록을 제출하고 보상 및 지급에 쓰이는 기록을 관리합니다. 풀이 수락한 셰어는 채굴 결과이며 지갑으로 즉시 지급되는 결제 거래는 아닙니다.

이 구성에서는 채굴 장비가 채굴용 블록체인 복사본을 직접 보관하지 않고 풀에 연결할 수 있습니다. 설정에는 [Blocknet 채굴 가이드](/ko/blog/how-to-mine-blocknet/)를, 채굴 활동과 결제 기록을 찾을 때는 [풀 추적 가이드](https://bntpool.com/blog/ko/track-your-miner-on-bntpool/)를 사용하세요. 풀 잔액과 지갑 잔액은 서로 다른 질문에 답합니다. 하나는 풀의 회계 기록이고, 다른 하나는 지갑이 체인에서 찾은 결제입니다.

## 어떤 앱을 계속 실행해야 하나요?

풀 채굴을 계속하려면 작동하는 풀 연결을 유지하고 seine를 실행해 두세요. 결제가 체인에 기록될 때 지갑 앱은 닫혀 있어도 됩니다. 다시 열면 노드와 지갑 스캔이 최신 상태에 도달하도록 기다리세요. 지갑이 별도 컴퓨터에 있다면 닫아도 채굴기가 멈추지 않습니다. seine를 실행하는 컴퓨터를 끄면 해당 채굴 작업이 중단됩니다.

연결된 Blocknet 셸을 닫는 것과 백그라운드 코어를 중지하는 것은 다르며, [코어 참고 문서](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md)가 이 차이를 설명합니다. [지갑 참고 문서](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-wallet.md)는 지갑 파일 경로를 기억해도 재시작 후 지갑을 자동으로 열지는 않는다고 설명합니다. 검토한 공식 클라이언트에서는 지갑이 다시 필요할 때 코어를 시작하고 셸에 연결한 다음 지갑 비밀번호로 `load`를 사용하세요.

## 채굴에 자체 노드가 필요한 때는 언제인가요?

풀 절차 대신 직접 채굴을 의도적으로 선택하면 자체 노드 연결이 필요합니다. seine의 daemon 모드에서는 채굴기가 실행 중인 코어에 작업을 요청하고 결과를 돌려보냅니다. 코어는 채굴 연결을 처리할 준비가 되어 있어야 하고 연결에는 인증이 필요합니다. 이 구성이 계속 작동하려면 채굴기와 코어 모두 사용 가능한 상태여야 합니다.

처음 풀을 설정할 때는 기본 풀 경로와 공개 지급 대상을 사용하세요. 모든 채굴 장비의 필수 조건으로 만들지 않고도 노드 운영을 별도로 배울 수 있습니다. 직접 연결을 원하면 [seine 솔로 채굴 문서](https://github.com/zpalmtree/seine/blob/8a822f767bdc6a8b2effd7565751f47ba2c6846d/docs/guides/solo-mining.md)의 구성 및 인증 요구 사항을 따르세요. 문제를 해결할 때 두 모드를 구분하세요. 풀 연결 문제와 로컬 코어 문제는 서로 다른 서비스와 관련됩니다.

## 원하는 작업에 따라 다음 단계를 고르세요

Blocknet을 받거나 보내고 싶다면 지갑과 노드 절차부터 시작하세요. 코인을 보유하거나 사용하는 데 채굴이 필요하지는 않습니다. 기존 지갑으로 채굴하려면 공개 지급 대상을 준비하고 seine를 풀에 맞게 설정하세요. 자체 직접 채굴 연결을 운영하려면 노드 설정을 추가하고 daemon 모드 지침을 따르세요.

소프트웨어를 바꾸기 전에 증상과 담당 구성 요소를 파악하세요. 채굴기가 보이지 않으면 채굴기와 풀 연결을 확인해야 합니다. 이미 보낸 결제가 지갑에 없다면 지갑 선택과 동기화를 확인해야 합니다. 지급되지 않은 풀 잔액은 풀의 회계 및 지급 정보를 확인해야 합니다. 이 첫 구분만으로도 관련 없는 앱을 다시 설치하지 않고 알맞은 가이드를 찾을 수 있는 경우가 많습니다.
