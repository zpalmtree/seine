작동하던 풀 연결과 시작 설정을 유지하면서 seine를 최신 릴리스로 유지합니다. 이 가이드는 공개 버전 v0.3.1을 기준으로 자동 업데이트의 작동 방식, 이전 버전에서 넘어올 때 한 번만 할 일, 직접 업데이트하는 방법을 설명합니다. 처음 설치한다면 [Windows](/ko/blog/mine-blocknet-on-windows/), [Linux](/ko/blog/mine-blocknet-on-linux/) 또는 [Mac](/ko/blog/mine-blocknet-on-mac/) 가이드를 사용하세요.

## seine는 어떻게 업데이트하나요?

<Answer>
seine를 그대로 실행해 두세요. 시작할 때와 12시간마다 새 릴리스를 확인하고, 채굴을 계속하면서 대시보드 헤더에서 60초를 카운트다운한 뒤 서명된 릴리스를 설치하고 같은 인자와 설정으로 재시작합니다. 직접 업데이트하려면 seine를 중지하고 공식 압축 파일의 파일로 교체한 뒤 같은 방식으로 시작하세요.
</Answer>

## 자동 업데이트는 어떻게 작동하나요?

새 릴리스가 나오면 헤더에 `update vX.Y.Z available`이 표시되고, 로그에 릴리스 링크가 나온 뒤 헤더에서 카운트다운이 시작됩니다(`updating to vX.Y.Z in 42s`). 카운트다운 중에도 채굴은 계속됩니다. `u`를 누르면 바로 업데이트하고, `s`를 누르면 그 버전을 건너뜁니다. seine는 건너뛴 버전을 데이터 디렉터리에 기억하고 다음 릴리스는 평소처럼 안내합니다.

카운트다운이 끝나면 seine는 릴리스 서명을 확인하고 새 실행 파일이 시작되는지 확인한 뒤에야 기존 파일을 교체합니다. 채굴을 깔끔하게 중지하고 같은 인자로 재시작하며, 새 대시보드 로그에 `updated to seine vX.Y.Z`가 표시됩니다. 새 버전은 저장된 튜닝으로 시작하고 릴리스에서 바뀐 부분만 시험하므로 빠르게 최고 속도로 돌아옵니다.

네트워크 업그레이드 때처럼 풀이 더 새로운 릴리스가 필요한 작업을 보내면, seine는 채굴을 일시 중지하고 건너뛴 버전이라도 바로 업데이트를 설치합니다. 알림만 받으려면 `--no-auto-update`, 확인 자체를 끄려면 `--disable-update-check`를 사용하세요. 직접 컴파일한 빌드는 알림만 표시하고 업데이트는 사용자에게 맡깁니다.

## 이전 버전에서 넘어올 때 한 번만 할 일은 무엇인가요?

대부분의 장비는 아무것도 할 필요가 없습니다. 일부 구성은 v0.3.1로 처음 자동 업데이트할 때 한 번만 조치가 필요합니다.

- **Linux, v0.2.45에서:** v0.2.45는 새 버전을 설치한 뒤 종료합니다. seine를 한 번 더 시작하세요. systemd 서비스처럼 seine를 자동으로 재시작하는 구성은 아무것도 할 필요가 없습니다.
- **Windows, v0.2.45 또는 v0.3.0에서:** 이전 버전이 새 버전을 실행하고 종료합니다. 종료 시 seine를 재시작하는 스크립트나 서비스도 사용한다면, seine가 하나만 실행되도록 업데이트 후 한 번 그것을 중지하세요.
- **HiveOS와 mmpOS, v0.3.0 패키지에서:** flight sheet나 프로필을 [릴리스 페이지](https://github.com/zpalmtree/seine/releases)의 v0.3.1 패키지로 바꾸세요. v0.3.1부터는 [HiveOS와 mmpOS 가이드](/ko/blog/mine-blocknet-hiveos-mmpos/)에서 보여 주듯 URL의 버전을 바꾸면 채굴 OS를 통해 패키지가 업그레이드됩니다.

## 현재 버전은 어떻게 확인하나요?

대시보드 헤더에 실행 중인 버전이 표시됩니다. 실제로 사용하는 실행 파일에 버전 명령을 실행해 확인할 수도 있습니다. 다른 폴더의 오래된 복사본은 바로가기나 서비스가 실행하는 것과 다를 수 있습니다. 반복 가능한 절차를 위해 실행 경로, 작업 디렉터리와 인자를 함께 기록합니다. Windows에서는 현재 채굴 프로그램 폴더에서 PowerShell을 여세요.

```powershell
.\seine.exe --version
```

Linux나 macOS에서는 해당 폴더에서 터미널을 여세요.

```sh
./seine --version
```

결과를 [공식 릴리스](https://github.com/zpalmtree/seine/releases)와 비교하고 플랫폼, 런타임과 시작 옵션 관련 릴리스 노트를 읽으세요.

## 어떤 설정을 보존해야 하나요?

기본적으로 `./seine-data/seine.config.json`을 읽습니다. `./`는 현재 작업 디렉터리이므로 프로그램을 옮겨 다른 곳에서 실행하면 설정 검색 위치도 바뀔 수 있습니다. `--data-dir`를 사용한다면 같은 디렉터리를 유지하세요. 절대 경로는 바로가기, 스크립트나 서비스가 작업 디렉터리를 선택할 때 위치를 명확히 합니다.

설정에는 채굴 모드, 지급 주소, 풀 URL과 기기 이름 등이 저장됩니다. 튜닝 파일을 포함한 데이터 디렉터리 전체를 보존하세요. 시작 명령, 스크립트나 서비스 정의도 저장합니다. `--backend`와 `--threads`는 저장된 연결 필드와 별개입니다. 둘 다 보존해야 재시작 후 의도한 설정이 유지됩니다.

## seine를 직접 업데이트하려면 어떻게 하나요?

`--no-auto-update`로 실행하거나 업데이트 시점을 직접 고르고 싶다면 직접 업데이트하세요. [다운로드 페이지](/ko/#download)나 공식 릴리스에서 운영체제와 CPU 아키텍처에 맞는 압축 파일을 선택하세요. 같은 릴리스의 별도 `SHA256SUMS.txt`도 받습니다. 체크섬을 비교한 뒤 별도 폴더에 풉니다. [검증 가이드](/ko/blog/antivirus-flags-crypto-miner/)는 Windows 절차와 다운로드 경고 처리를 설명합니다.

패키지의 파일을 함께 유지하세요. Windows 패키지는 `seine.exe` 옆에 NVIDIA 런타임 라이브러리를 포함하므로 실행 파일만 복사하면 버전이 섞일 수 있습니다. [NVIDIA 가이드](/ko/blog/mine-blocknet-nvidia-gpu/)는 런타임 설정을 다룹니다. [v0.3.1 설정 문서](https://github.com/zpalmtree/seine/blob/v0.3.1/docs/guides/configuration.md)는 여기서 설명하는 저장 설정, 자동 업데이트와 시작 동작을 문서화합니다.

## 중지, 백업 및 교체

`q` 또는 `Ctrl+C`로 종료하고 프로세스가 끝날 때까지 기다립니다. 서비스는 관리자를 사용하고 파일 교체 전 자동 재시작 정책을 고려하세요. 중지 상태에서 앱과 데이터 폴더를 로컬에 백업합니다. 새로 푼 파일과 분리해 두 버전을 구별하세요.

원래 데이터를 보존하며 새 앱 파일을 설치 위치에 놓습니다. 버전별 폴더를 쓴다면 바로가기나 서비스의 실행 경로를 갱신하고 작업 디렉터리와 데이터 경로를 명시적으로 유지하세요. 같은 옵션으로 하나의 인스턴스를 시작합니다. 여러 기기는 먼저 한 대의 검증을 완료하세요.

## 업데이트 성공을 어떻게 확인하나요?

설치한 실행 파일의 버전을 다시 확인해 받은 릴리스와 비교합니다. 실행 후 지급 대상, 풀, 기기 이름과 원하는 CPU/GPU 백엔드를 확인하세요. 호환되는 튜닝 기록은 재사용될 수 있습니다. 해시레이트 평가 전 시작 튜닝 완료를 기다리세요. [대시보드 가이드](/ko/blog/seine-dashboard-explained/)가 각 패널을 설명합니다.

승인된 셰어를 확인하고 같은 주소의 [My Stats](https://bntpool.com/stats)를 여세요. 풀 추정치는 셰어와 안정화 시간이 필요하므로 즉각적인 해시레이트 차이만으로 업데이트 문제를 판단할 수 없습니다. 새 프로세스는 새 로컬 세션도 시작합니다. 단기 카운터보다 주소, 기기와 활동을 먼저 비교하세요.

## 초기 설정 질문이 다시 나타나면?

작업 디렉터리와 `--data-dir`부터 확인하세요. 새 폴더에는 기본 상대 경로에 기존 설정이 없을 수 있습니다. 해당 인스턴스를 중지하고 원래 데이터를 지정하세요. 오류가 설정 파일을 지목하면 파일과 정확한 메시지를 보존합니다. 공개 이미지나 보고서에 시드 문구, 개인 키나 제어 API 토큰을 넣지 마세요.

시작 실패 시 버전, 운영체제, 실행 경로와 정확한 오류를 기록하고 해당 플랫폼 가이드를 따르세요. 백업은 이전 앱과 설정을 함께 보존합니다. 복원 전 새 릴리스 노트의 호환성 조건을 확인하세요. 알려진 설정으로 재개하고 셰어를 다시 검증하세요. 채굴 프로그램 교체만을 위해 지갑을 새로 만들 필요는 없습니다.
