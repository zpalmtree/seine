换电脑前先备份 Blocknet 钱包，再通过钱包文件或恢复种子恢复同一地址。本指南依据 2026 年 10 月 27 日检查的官方 CLI v1.2.0 和 core v0.22.0，将制作备份、在别处打开及验证恢复完成分开说明。

## 如何备份和恢复 Blocknet 钱包？

<Answer>
离线保存恢复种子，并单独保存完整钱包文件副本。在目标电脑用密码加载文件，或将原种子导入新文件。比较完整收款地址，让节点和钱包扫描赶上，核实记录后再停止使用旧副本。
</Answer>

## 选择实际具备的恢复方式

文件备份和恢复种子用途不同。`.wallet.dat` 文件包含钱包密钥和已存状态；打开受密码保护的副本需要其密码。种子可在新文件中用新密码重建基于种子的钱包密钥。有条件时两者都保留，私密付款记录另存，便于恢复后比较。

本流程针对已有完整钱包。首次创建请按[钱包设置指南](/zh-hans/blog/blocknet-wallet-for-mining/)操作。在第二台电脑监控付款而不具备花费权限，请用[只读指南](/zh-hans/blog/blocknet-view-only-wallet/)。公开收款地址本身无法恢复钱包。选择步骤前，先确认有无完整文件、密码和原始种子。

## 准备原钱包和恢复记录

从终端连接正在运行的 mainnet core：

```sh
blocknet attach mainnet
```

在交互式 shell 中加载目标钱包并记录完整公开地址：

```text
load
address
```

使用已有钱包的菜单项。如另一个钱包已加载，先使用 `unload`。将地址、网络和文件名保存在私密迁移笔记中。

对于种子钱包，在 shell 中运行 `seed`，确认提示并输入密码。按准确顺序写下返回的词语，离线保存。不要在共享或录制屏幕时操作；[种子指南](/zh-hans/blog/seed-phrase-explained/)说明如何保护记录。如客户端报告没有种子，请保留完整文件及密码，使用复制文件的方式。不要假定所有旧钱包或导入密钥的钱包都有种子。

## 单独复制钱包文件

找到 core 实际使用的文件。默认钱包目录是 `~/.config/bnt/wallets/`，Windows 上为 `C:\Users\<you>\.config\bnt\wallets\`。配置的 `wallet_file` 所在文件夹可能不同。使用官方客户端显示的路径及[钱包管理资料](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-wallet.md)，尤其是存在相似文件名时。复制前确认目标文件。

记录地址后运行 `unload`，等待成功再复制。原文件留在原处，将带日期的副本保存到自己控制的独立存储中。保留 `.wallet.dat` 扩展名，保护备份和密码。客户端从其他目录加载时可能建立本地备份，但不会覆盖已有同名备份。检查自己保存的副本，不要假定本地副本是最新的。

## 如何迁移到新电脑？

安装[官方客户端](https://github.com/blocknetprivacy/blocknet/releases/latest)，按[节点指南](/zh-hans/blog/run-blocknet-node/)准备 mainnet core。通过自己控制的存储，将完整文件的副本移入目标 core 的钱包文件夹。保留其中无关的现有文件，必要时选择不同文件名。已检查的客户端中，即使输入自定义路径，`load` 也从该钱包文件夹读取。

在目标电脑通过 attach 连接并运行 `load`，选择复制文件，输入原密码。菜单中没有文件时，确认 core 使用哪个文件夹，以及实际复制位置。选择已有文件，不要选择创建新钱包。复制同一文件恢复的是同一密钥访问，不会发送币或创建第二份余额。

## 通过原始恢复种子恢复

文件丢失或忘记密码时，在可信目标电脑的官方客户端中使用保存的种子。连接目标 mainnet core，先卸载其他钱包。在交互式 shell 启动恢复提示：

```text
import
```

选择选项 1，使用 12 词恢复种子。按顺序输入自己的原始词语；切勿使用指南中的示例词或把种子粘贴到网站。

选择尚未使用的新钱包名称，按提示设置并确认新密码。[已检查的导入实现](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go)根据恢复输入创建钱包并报告地址。原加密文件保留旧密码。检查导入钱包期间保留旧文件和备份，把新文件也视为需要保护的另一份副本。

## 检查地址、链和钱包扫描

加载或导入后检查目标钱包：

```text
address
status
balance
history
```

将整个地址与先前记录比较。地址检查在依赖余额之前先确认钱包身份。如有不同，停止迁移，重新检查所选文件、恢复词和网络。排查期间保持原备份完整。

让节点链下载和钱包输出扫描都赶上。新导入钱包需要在链上寻找输出，初期余额不是恢复的最终检查。扫描完成后比较可用余额与入账记录。为历史细节保留单独的付款笔记和原文件。[钱包同步指南](/zh-hans/blog/blocknet-wallet-not-syncing/)说明应查看哪些进度，以及何时适合重新扫描。

## 验证后完成迁移

保存已验证目标钱包的受保护备份，并保留离线种子。记录哪台电脑持有正在使用的完整钱包、哪些是备份。旧副本仍拥有相同密钥访问，迁移文件不会撤销它。淘汰设备时，先确认备份可用，再按平常的安全处置流程处理存储。

如果恢复地址匹配，现有挖矿收款目标可以不变。核实挖矿收入时，将[矿池付款记录](https://bntpool.com/blog/zh-hans/track-your-miner-on-bntpool/)与钱包入账历史比较。如果刻意创建不同钱包，那是地址变更，不是恢复。完成恢复钱包的验证后，再单独更改矿工配置。
