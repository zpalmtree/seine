換電腦前先備份 Blocknet 錢包，再透過錢包檔案或復原種子還原同一地址。本指南依據 2026 年 10 月 27 日檢查的官方 CLI v1.2.0 和 core v0.22.0，將製作備份、在別處開啟及驗證復原完成分開說明。

## 如何備份和還原 Blocknet 錢包？

<Answer>
離線儲存復原種子，並單獨儲存完整錢包檔案副本。在目標電腦用密碼載入檔案，或將原種子匯入新檔案。比較完整收款地址，讓節點和錢包掃描趕上，核實紀錄後再停止使用舊副本。
</Answer>

## 選擇實際具備的復原方式

檔案備份和復原種子用途不同。`.wallet.dat` 檔案包含錢包金鑰和已存狀態；開啟受密碼保護的副本需要其密碼。種子可在新檔案中用新密碼重建以種子為基礎的錢包金鑰。可以時兩者都保留，私密付款紀錄另存，方便還原後比較。

本流程針對既有完整錢包。首次建立請按[錢包設定指南](/zh-hant/blog/blocknet-wallet-for-mining/)操作。在第二台電腦監控付款而不具備花費權限，請用[唯讀指南](/zh-hant/blog/blocknet-view-only-wallet/)。公開收款地址本身無法復原錢包。選擇步驟前，先確認有無完整檔案、密碼和原始種子。

## 準備原錢包和復原紀錄

從終端機連接正在執行的 mainnet core：

```sh
blocknet attach mainnet
```

在互動式 shell 載入目標錢包並記錄完整公開地址：

```text
load
address
```

使用既有錢包的選單項目。如另一個錢包已載入，先使用 `unload`。將地址、網路和檔名儲存在私密移轉筆記中。

對於種子錢包，在 shell 中執行 `seed`，確認提示並輸入密碼。按準確順序寫下傳回的詞語，離線儲存。不要在分享或錄製螢幕時操作；[種子指南](/zh-hant/blog/seed-phrase-explained/)說明如何保護紀錄。如用戶端報告沒有種子，請保留完整檔案及密碼，使用複製檔案方式。不要假定所有舊錢包或匯入金鑰的錢包都有種子。

## 單獨複製錢包檔案

找到 core 實際使用的檔案。預設錢包目錄是 `~/.config/bnt/wallets/`，Windows 上為 `C:\Users\<you>\.config\bnt\wallets\`。設定的 `wallet_file` 所在資料夾可能不同。使用官方用戶端顯示的路徑及[錢包管理資料](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-wallet.md)，尤其是存在相似檔名時。複製前確認目標檔案。

記錄地址後執行 `unload`，等待成功再複製。原檔案留在原處，將帶日期的副本儲存到自己控制的獨立儲存裝置。保留 `.wallet.dat` 副檔名，保護備份和密碼。用戶端從其他目錄載入時可能建立本機備份，但不會覆寫既有同名備份。檢查自己儲存的副本，不要假定本機副本是最新的。

## 如何移轉到新電腦？

安裝[官方用戶端](https://github.com/blocknetprivacy/blocknet/releases/latest)，按[節點指南](/zh-hant/blog/run-blocknet-node/)準備 mainnet core。透過自己控制的儲存裝置，將完整檔案副本移入目標 core 的錢包資料夾。保留其中無關的既有檔案，必要時選擇不同檔名。已檢查的用戶端中，即使輸入自訂路徑，`load` 也從該錢包資料夾讀取。

在目標電腦透過 attach 連接並執行 `load`，選擇複製檔案，輸入原密碼。選單沒有檔案時，確認 core 使用哪個資料夾及實際複製位置。選擇既有檔案，不要選擇建立新錢包。複製同一檔案恢復的是同一金鑰存取，不會傳送幣或建立第二份餘額。

## 透過原始復原種子還原

檔案遺失或忘記密碼時，在可信目標電腦的官方用戶端使用儲存的種子。連接目標 mainnet core，先卸載其他錢包。在互動式 shell 啟動復原提示：

```text
import
```

選擇選項 1，使用 12 詞復原種子。按順序輸入自己的原始詞語；切勿使用指南中的範例詞或把種子貼到網站。

選擇尚未使用的新錢包名稱，按提示設定並確認新密碼。[已檢查的匯入實作](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go)根據復原輸入建立錢包並報告地址。原加密檔案保留舊密碼。檢查匯入錢包期間保留舊檔案和備份，把新檔案也視為需要保護的另一份副本。

## 檢查地址、鏈和錢包掃描

載入或匯入後檢查目標錢包：

```text
address
status
balance
history
```

將整個地址與先前紀錄比較。地址檢查在依賴餘額之前先確認錢包身分。如有不同，停止移轉，重新檢查所選檔案、復原詞和網路。排查期間保持原備份完整。

讓節點鏈下載和錢包輸出掃描都趕上。新匯入錢包需要在鏈上尋找輸出，初期餘額不是復原的最終檢查。掃描完成後比較可用餘額與入帳紀錄。為歷史細節保留單獨的付款筆記和原檔案。[錢包同步指南](/zh-hant/blog/blocknet-wallet-not-syncing/)說明應查看哪些進度及何時適合重新掃描。

## 驗證後完成移轉

儲存已驗證目標錢包的受保護備份，並保留離線種子。記錄哪台電腦持有使用中的完整錢包、哪些是備份。舊副本仍有相同金鑰存取權，移轉檔案不會撤銷它。淘汰裝置時，先確認備份可用，再按平常的安全處置流程處理儲存裝置。

如果還原地址相符，既有挖礦收款目標可以不變。核實挖礦收入時，將[礦池付款紀錄](https://bntpool.com/blog/zh-hant/track-your-miner-on-bntpool/)與錢包入帳歷史比較。如果刻意建立不同錢包，那是地址變更，不是還原。完成還原錢包驗證後，再單獨更改礦工設定。
