## What is the best hardware for Blocknet mining?

<Answer>
The fastest configuration in these measurements is an AMD EPYC 9355P at 97.1 H/s: 64 mining threads and 192 GiB of RAM on Linux with seine's default settings. Blocknet mining benefits from memory bandwidth and enough RAM for 2 GiB per thread. NVIDIA cards can add their hashrate alongside the CPU.
</Answer>

Blocknet's proof of work is Argon2id with a 2 GiB memory block per hash. That makes it [memory-hard](/blog/argon2id-proof-of-work-explained/): hashrate depends as much on memory bandwidth and latency as on core count, and on how many of those 2 GiB blocks fit in RAM at once. A strong memory system is what the top machines in the table below have in common.

## Why memory bandwidth sets your hashrate

Each Argon2id hash fills its entire 2 GiB block once and, while doing so, reads earlier parts of it back. A processor's L3 cache is measured in megabytes: on the Zen 5 server, each group of eight cores shares 32 MiB, so a single hash works through 64 times more memory than that cache holds. Most of the work is memory traffic.

Three things follow when you choose hardware:

- **Memory bandwidth counts as much as cores.** Weigh the memory system as heavily as the core count when you compare machines.
- **RAM sets the thread ceiling.** Every thread needs its own 2 GiB block, so RAM often limits the thread count before cores do.
- **The kernel matters on the same chip.** Seine compares the available CPU kernels while mining and selects one for your machine.

## How much RAM do you need for each mining thread?

<Answer>
Each mining thread needs about 2 GB of RAM, because every hash fills its own 2 GiB block of memory. Divide your RAM by two for the most threads that fit, then subtract a little for the operating system. Seine does this sum for you and keeps 5% (at most 1 GiB by default) of RAM in reserve.
</Answer>

Here is the arithmetic for common sizes. "On paper" is RAM ÷ 2 GiB. The last column subtracts seine's 5% (at most 1 GiB by default) reserve and about 2-3 GB for the operating system, so treat it as a rough guide. For laptops and older PCs with 4-12 GB, see the guide to [mining on an old PC or laptop](/blog/mine-crypto-on-old-pc-or-laptop/).

| RAM | Memory blocks on paper | Threads seine can run, roughly |
|---|---|---|
| 16 GB | 8 | 6 |
| 32 GB | 16 | 14 |
| 64 GB | 32 | 30 |
| 128 GB | 64 | 62 |

Seine also caps threads at the processor's logical core count, so the real limit is whichever runs out first. Take a 16-core desktop processor with 32 hardware threads. With 32 GB of RAM it runs about 14 mining threads, and with 64 GB about 30. To run 32 threads you need 64 GiB for the memory blocks alone plus headroom, which is why the 32-thread Zen 5 result came from a machine with 128 GiB.

If you're buying RAM for mining, match it to the threads you want: about 2 GB per thread, plus a few gigabytes for the system.

## Can you mine Blocknet with your CPU and NVIDIA GPU together?

Yes. On Windows and Linux, seine mines on every CPU core and every NVIDIA graphics card it detects at the same time, and the hashrates add up. You don't need a flag for this; it is the default.

- **Windows:** the download includes the CUDA runtime libraries, so you only need an up-to-date NVIDIA driver.
- **Linux:** the NVIDIA driver is all you need.
- **First launch:** seine tunes its kernel settings for each card and caches the result, so later starts take seconds.

On [Apple Silicon Macs](/blog/mine-blocknet-on-mac/), seine mines on the CPU by default, the fastest setup measured on the M4 Max. The [NVIDIA guide](/blog/mine-blocknet-nvidia-gpu/) covers multi-GPU rigs and requirements.

## What does seine tune automatically?

For everyday mining, run seine, paste your address or `@name`, and accept the default pool, bntpool.com. The [mining guide](/blog/how-to-mine-blocknet/) walks through those steps. The manual EPYC result above has its own settings; automatic mining does the following:

- **Sizes the thread count** to your RAM and cores, then compares thread counts on real mining work and keeps the best one.
- **Picks the CPU kernel**, such as AVX2, AVX-512, the streaming kernel on Zen 5 EPYC or SHA3 on Arm, switching only after two confirmed gains.
- **Places threads on big servers.** On Linux, it spreads threads across NUMA nodes and L3 cache groups, which added 16.7% on a rented EPYC 8434P at 24 threads. The [guide to mining on servers](/blog/mine-blocknet-on-servers/) has the details.
- **Protects your memory.** It keeps a 5% (at most 1 GiB by default) reserve, parks threads if RAM gets tight and brings them back when it frees up.
- **Remembers what worked**, so the next start begins from the tuned settings.

None of this reconnects to the pool, so tuning costs you no mining time. The [automatic tuning guide](https://github.com/zpalmtree/seine/blob/master/docs/guides/autotuning.md) explains each step.

One optional extra is worth doing on Linux and WSL: reserving huge pages added about 4-6% with 2 MiB pages and a further 2% with 1 GiB pages on the validation machine. The [huge pages guide](/blog/huge-pages-blocknet-mining/) has the commands, and the [large servers guide](https://github.com/zpalmtree/seine/blob/master/docs/guides/large-servers.md) covers EPYC and Xeon machines.

## How do you check your own hashrate?

The quickest way is to [download seine](/#download) and start mining: the dashboard shows your hashrate within moments, and you can look up your address on [bntpool.com](https://bntpool.com) to see what the pool records. Give the tuner a little time to settle before you read the number.

To measure the processor without connecting to a pool, run seine's offline benchmark:

```sh
./seine --bench --bench-kind backend --backend cpu --bench-secs 20 --bench-rounds 3
```

It reports completed hashes per second, the same measure the table above uses, so you can compare your machine with the [published results](/#performance).
