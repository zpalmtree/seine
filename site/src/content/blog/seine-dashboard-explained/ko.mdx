seine를 시작하면 바로 실시간 대시보드가 열립니다. 해시 계산 속도, 풀이 승인한 셰어 수, 받을 금액, 튜닝 진행 상황, 그리고 seine가 하는 일의 로그를 보여 줍니다. 이 둘러보기는 seine v0.3.1을 패널별로 살펴보며 각 레이블의 의미와 숫자의 출처를 설명하고, 채굴 중 쓸 수 있는 키를 다룹니다.

![bntpool.com에서 채굴 중인 seine v0.3.1 터미널 대시보드: CPU 스레드 21개로 현재 해시레이트 16.63 H/s, 튜닝 완료, 셰어 승인 222개와 거부 1개, 최소 지급액 1 BNT가 표시된 풀 잔액, 승인된 셰어 로그](/assets/blog/seine-dashboard-v031.webp "seine v0.3.1 대시보드")

이 그림은 seine v0.3.1의 대시보드 코드 자체를 120 × 26 문자 크기로 데모 값과 함께 렌더링한 것입니다. Ryzen 9 9950X가 측정된 16.63 H/s, 21스레드로 bntpool.com에서 세션을 시작한 지 2시간 된 상태입니다. 주소는 줄인 가상의 주소입니다. 이 글의 나머지는 이 그림을 기준으로 설명합니다.

## seine 대시보드에는 무엇이 표시되나요?

<Answer>
seine 대시보드에는 실시간 및 평균 해시레이트, 완료한 해시 수, 체인 높이와 네트워크 해시레이트, 채굴기 상태, 셰어 난이도와 거부 및 승인된 셰어, 장치별 해시레이트, 풀, 스레드 수와 튜닝 상태, bntpool.com 잔액, 거슬러 올라가 스크롤할 수 있는 로그가 표시됩니다. 약 1초마다 새로 고쳐집니다.
</Answer>

위에서 아래로 헤더, 세 개의 통계 패널(`HASHRATE`, `NETWORK`, `MINING`), `DEVICES`, `CONFIG`, `POOL BALANCE`, `LOG` 순서로 패널이 배치됩니다. 넓은 터미널에서는 `CONFIG`와 잔액 패널이 나란히 표시됩니다.

대시보드는 채굴이 시작되기 전에 열립니다. 첫 실행에서 seine는 대시보드 안에서 지급 주소와 풀을 묻고, 이어서 하드웨어 점검과 시작 진행 상황을 화면에 보여 주므로 각 단계를 따라갈 수 있습니다.

## 헤더: 버전, 물결, 업데이트

헤더 제목에는 seine 버전이 표시됩니다. 여기서는 `seine v0.3.1`입니다. 새 릴리스가 나오면 `update vX.Y.Z available`이 표시되고, 이어서 자동 설치까지의 카운트다운 `updating to vX.Y.Z in 42s`가 옆의 `u now  s skip`과 함께 표시됩니다. `u`를 누르면 바로 설치하고 `s`를 누르면 그 버전을 건너뜁니다. 카운트다운 중에도 채굴은 계속되며, 그다음 과정은 [업데이트 가이드](/ko/blog/update-seine-miner/)에서 설명합니다.

제목 아래에는 두 줄의 물결이 1초에 한 단계씩 흘러갑니다. 풀이 셰어를 승인하거나 장비가 블록을 찾을 때마다 금색 다이아몬드가 위쪽 줄 오른쪽 끝에 나타나 1초에 한 칸씩 왼쪽으로 이동합니다. 너비가 약 120칸인 터미널에서는 보이는 다이아몬드가 최근 2분 정도의 승인된 작업입니다. 아래쪽 줄 끝에는 `uptime`이 있습니다.

## seine는 해시레이트를 어떻게 측정하나요?

`HASHRATE` 패널에는 세 줄이 있습니다.

- **Current**는 최근 5초 구간의 해시레이트입니다. 여기서 해시 하나는 2 GiB Argon2id 계산 하나를 완료한 것이므로, H/s는 초당 완료한 해시 수입니다. NVIDIA GPU는 작업을 몰아서 끝내기 때문에, GPU의 현재 해시레이트는 안정적으로 보이도록 30초 구간을 사용합니다.
- **Average**는 이번 세션의 모든 해시를 채굴에 쓴 시간으로 나눈 값입니다. 노드 동기화를 기다리거나 잘못된 주소 이후처럼 기다리는 시간은 빠집니다.
- **Total**은 seine를 시작한 이후 완료한 해시 수입니다.

그림에서 Current는 16.63 H/s, Average는 16.41 H/s입니다. Average가 낮게 시작하는 이유는 각 스레드가 첫 해시를 마무리하는 중이고 튜닝이 아직 스레드 수를 고르는 처음 몇 분이 포함되기 때문입니다. seine를 오래 실행할수록 두 값이 가까워집니다.

## 네트워크, 상태, 셰어

`NETWORK` 패널에는 채굴 중인 체인의 `Height`와 네트워크 전체의 `Global` 해시레이트가 표시됩니다. 풀 모드에서 seine는 이 값을 bntpool.com의 공개 통계에서 읽어 옵니다.

`State`는 채굴기가 무엇을 하는지 알려 줍니다. 초록색 `working`이 보고 싶은 상태입니다. 풀 모드에서는 시작하거나 다시 연결할 때 다음 상태도 보입니다.

| State | 의미 |
|---|---|
| `pool-connecting` | Stratum 연결을 여는 중 |
| `pool-connected` | 연결됨, 로그인 중 |
| `pool-authenticated` | 로그인이 승인되어 첫 작업을 기다리는 중 |
| `working` | 현재 작업으로 해시 계산 중 |
| `pool-disconnected` | 연결이 끊김. seine가 스스로 다시 연결합니다 |
| `pool-login-rejected` | 풀이 로그인을 거부함. 이유는 로그에 표시됩니다 |

자신의 노드에서 솔로 채굴하면 `daemon-syncing`, `stale-tip` 같은 상태가 추가됩니다. seine가 무언가를 기다리는 동안에는 실제로 내지 않는 속도를 보여 주지 않도록 Current가 0으로 떨어집니다.

`MINING` 패널은 이번 세션의 셰어를 셉니다.

- **Difficulty:** 풀이 이 장비에 설정한 셰어 난이도입니다.
- **Rejected:** 풀이 승인하지 않은 셰어입니다.
- **Accepted:** 풀이 나에게 반영한 셰어입니다.

bntpool.com은 해시레이트와 상관없이 셰어가 꾸준히 들어오도록 장비마다 셰어 난이도를 조정하므로, 빠른 장비일수록 난이도가 높아집니다. 지급은 승인된 셰어를 따릅니다. daemon 모드에서는 이 패널에 `Submitted`, `Stale`, `Accepted`가 표시되며, 자신의 노드로 보낸 솔루션을 셉니다.

## 장치, 설정, 풀 잔액

`DEVICES`에는 각 채굴 백엔드와 현재 및 평균 해시레이트가 나열됩니다. CPU는 `cpu#1`, 각 GPU는 `nvidia#1`, `amd#1` 등입니다. GPU는 CPU가 이미 채굴하는 동안 백그라운드에서 시작되며, 아직 시작 중인 카드는 온라인이 될 때까지 진행 상황을 보여 줍니다.

`CONFIG`에는 이번 실행의 설정이 표시됩니다.

- **Pool**은 풀 주소이며 기본값은 `bntpool.com:3333`입니다. daemon 모드에서는 `Daemon`과 노드의 API 주소가 표시됩니다.
- **Threads**는 CPU 채굴 스레드 수입니다. 키를 쓸 수 있을 때는 옆에 `[+] [-]`가 나타납니다. **Worker**는 이 컴퓨터가 풀에 로그인할 때 쓰는 장비 이름입니다.
- **Tuning**은 CPU 자동 튜닝을 보여 줍니다. 무엇을 비교하는지와 남은 시간을 표시하다가 끝나면 `done`이 됩니다. 각 상태는 [CPU 튜닝 가이드](/ko/blog/seine-automatic-cpu-tuning/)에서 설명합니다.

풀에서 장비를 알아보기 쉬운 이름으로 표시하려면 시작할 때 지정하세요.

```sh
./seine --pool-worker rig-01
```

`POOL BALANCE`는 몇 초마다 bntpool.com에서 잔액을 읽어 옵니다. `Pending`은 벌었지만 아직 지급되지 않은 금액으로, 아직 성숙 중인 블록의 예상 보상도 포함합니다. `Paid`는 풀이 주소로 보낸 금액이며, 오른쪽의 `Miner`는 앞뒤 여섯 글자로 줄인 내 주소입니다. 주소 앞에 `solo:`를 붙여 풀에서 솔로 채굴하면 이 레이블이 `Solo`로 표시됩니다. `Min payout`은 풀의 최소 지급액으로, bntpool.com에서는 1 BNT입니다. daemon 모드에서는 이 패널이 `WALLET`으로 바뀌며, 노드 지갑의 `Pending`과 `Unlocked` 잔액을 보여 줍니다.

## 로그 읽기

`LOG`에는 seine가 하는 일이 최신 항목이 아래로 오도록 나열되며, 각 줄에 태그와 얼마나 전에 일어났는지가 붙습니다. 같은 줄이 반복되면 `share accepted ×104`처럼 횟수가 붙은 한 줄로 합쳐지므로, 긴 세션에서도 로그를 읽기 쉽습니다. 풀에서 가장 자주 보는 태그는 다음과 같습니다.

- `CONN`: 풀 연결. 예: `connected to pool`
- `SHARE`: `share accepted` 또는 이유가 붙은 거부
- `CPU`: 튜닝 결과. 예: `tuned to 21 threads`
- `BACKEND`: 장치 시작. 예: `cpu: starting 21 threads (~42.0 GiB RAM)`

로그는 기본적으로 필요한 내용을 보여 줍니다. 내부 설정과 새 작업 같은 일상적인 동작도 보려면 `--verbose`를 추가하세요.

## 대시보드에서 어떤 키를 쓸 수 있나요?

<Answer>
Tuning 행이 done이 되면 + 또는 =로 CPU 스레드를 하나 늘리고 -로 하나 줄입니다. 화살표 키, PgUp, PgDn, Home으로 로그를 거슬러 올라가며 스크롤하고, End로 다시 새 줄을 따라갑니다. 업데이트 카운트다운 중에는 u로 바로 설치하고 s로 그 버전을 건너뜁니다. 종료하려면 q 또는 Ctrl+C를 누르세요.
</Answer>

스레드 변경은 실행 중인 CPU 스레드에 바로 적용되며, GPU와 풀 연결은 계속 동작합니다. 튜닝이 아직 스레드 수를 고르는 중이면 키 입력은 대기하고 대시보드에 튜닝의 남은 시간이 표시됩니다. 키 입력은 해당 실행에만 적용되며, 다음 시작 때는 다시 저장된 튜닝 결과를 사용합니다. 처음부터 수를 고정하려면 `--threads`를 사용하세요.

로그를 거슬러 올라가는 동안에는 로그 제목이 `LOG  paused, End to follow`로 바뀌고, `End`를 누를 때까지 화면이 멈춰 있습니다.

## 작은 터미널과 일반 출력

너비가 80칸보다 좁은 터미널에서는 세 통계 패널이 세로로 쌓입니다. 높이가 낮은 창에서는 seine가 간단한 화면으로 바꿔 로그 위에 Threads, State, Current, Average를 계속 표시합니다. 기본값인 `--ui auto`는 대화형 터미널에서만 대시보드를 보여 주고, `--ui plain`은 서버, 로그 파일, 프로세스 관리자를 위한 일반 스크롤 로그를 출력합니다.

아직 seine를 설정하지 않았다면 [Blocknet 채굴 가이드](/ko/blog/how-to-mine-blocknet/)에서 다운로드부터 첫 승인 셰어까지 안내합니다.
