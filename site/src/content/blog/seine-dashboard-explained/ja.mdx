seine を起動すると、すぐにライブのダッシュボードが開きます。ハッシュ計算の速さ、プールが受理したシェアの数、受け取れる金額、チューニングの進み具合、そして seine の動作のログです。このツアーでは seine v0.3.1 をパネルごとに見ていき、各ラベルの意味とその数値がどこから来るのかを説明し、マイニング中に使えるキー操作を紹介します。

この画像は、seine v0.3.1 のダッシュボードのコードそのものを 120 × 26 文字でデモ用の値とともに描画したものです。Ryzen 9 9950X が実測の 16.63 H/s・21 スレッドで、bntpool.com でのセッション開始から 2 時間たった状態です。アドレスは短縮した架空のものです。この記事の残りはこの画像を基準に説明します。

## seine のダッシュボードには何が表示されますか？

<Answer>
seine のダッシュボードには、現在と平均のハッシュレート、完了したハッシュ数、チェーンの高さとネットワークのハッシュレート、マイナーの状態、シェアの難易度と拒否・受理されたシェア、各デバイスのハッシュレート、プール、スレッド数とチューニングの状況、bntpool.com の残高、さかのぼってスクロールできるログが表示されます。表示は約 1 秒ごとに更新されます。
</Answer>

上から順に、ヘッダー、3 つの統計パネルの行（`HASHRATE`、`NETWORK`、`MINING`）、`DEVICES`、`CONFIG`、`POOL BALANCE`、`LOG` のパネルが並びます。幅の広いターミナルでは、`CONFIG` と残高パネルが横に並びます。

ダッシュボードはマイニングが始まる前に開きます。初回起動時には、seine はダッシュボードの中で支払いアドレスとプールを尋ね、その後ハードウェアのチェックと起動の進み具合を画面に表示するので、各段階を追うことができます。

## ヘッダー：バージョン、波、更新

ヘッダーのタイトルには seine のバージョンが表示されます。ここでは `seine v0.3.1` です。新しいリリースが出ると `update vX.Y.Z available` と表示され、続いて自動インストールまでのカウントダウン `updating to vX.Y.Z in 42s` が、その横の `u now  s skip` とともに表示されます。`u` を押すとすぐにインストールし、`s` を押すとそのバージョンをスキップします。カウントダウン中もマイニングは続き、その後の流れは[更新ガイド](/ja/blog/update-seine-miner/)で説明しています。

タイトルの下では、2 行の波が 1 秒に 1 ステップずつ流れていきます。プールがシェアを受理するたび、またはリグがブロックを見つけるたびに、金色のダイヤモンドが上の行の右端に現れ、1 秒に 1 列ずつ左へ流れます。幅が約 120 列のターミナルでは、見えているダイヤモンドは直近 2 分ほどの受理された作業です。下の行の末尾には `uptime` があります。

## seine はハッシュレートをどのように測定していますか？

`HASHRATE` パネルには 3 つの行があります。

- **Current** は、直近 5 秒間の移動ウィンドウでのハッシュレートです。ここでの 1 ハッシュは 2 GiB の Argon2id 計算 1 回分なので、H/s は 1 秒あたりに完了したハッシュ数を数えています。NVIDIA GPU は作業をまとめて完了させるので、値を安定させるために 30 秒のウィンドウを使います。
- **Average** は、このセッションのすべてのハッシュをマイニングに使った時間で割った値です。ノードの同期や無効なアドレスの後など、待機していた時間は除外されます。
- **Total** は、seine を起動してから完了したハッシュの数です。

画像では Current が 16.63 H/s、Average が 16.41 H/s です。Average が低めから始まるのは、各スレッドが最初のハッシュを仕上げている途中で、チューニングもまだスレッド数を選んでいる最初の数分間を含むためです。seine を長く動かすほど、2 つの値は近づきます。

## ネットワーク、状態、シェア

`NETWORK` パネルには、マイニング中のチェーンの `Height` と、ネットワーク全体の `Global` ハッシュレートが表示されます。プールモードでは、seine はこの値を bntpool.com の公開統計から読み取ります。

`State` はマイナーが何をしているかを示します。緑の `working` が見たい状態です。プールモードでは、起動時や再接続時に次の状態も表示されます。

| State | 意味 |
|---|---|
| `pool-connecting` | Stratum 接続を開いている |
| `pool-connected` | 接続済み、ログイン中 |
| `pool-authenticated` | ログインが受理され、最初のジョブを待っている |
| `working` | 現在のジョブでハッシュを計算中 |
| `pool-disconnected` | 接続が切れた。seine は自動で再接続します |
| `pool-login-rejected` | プールがログインを拒否した。理由はログに表示されます |

自分のノードでのソロマイニングでは、`daemon-syncing` や `stale-tip` などの状態が加わります。seine が何かを待っている間は、実際には出していない速度を表示しないよう、Current が 0 になります。

`MINING` パネルは、このセッションのシェアを数えます。

- **Difficulty：** プールがこのリグに設定したシェアの難易度。
- **Rejected：** プールが受理しなかったシェア。
- **Accepted：** プールがあなたの分として記録したシェア。

bntpool.com は、ハッシュレートにかかわらず一定のペースでシェアが届くよう、リグごとにシェアの難易度を調整します。そのため速いリグほど難易度が高くなります。支払いは受理されたシェアに従います。daemon モードでは、このパネルに `Submitted`、`Stale`、`Accepted` が表示され、自分のノードへ送ったソリューションを数えます。

## デバイス、設定、プール残高

`DEVICES` には、各マイニングバックエンドとその現在・平均のハッシュレートが並びます。CPU は `cpu#1`、各 GPU は `nvidia#1`、`amd#1` などです。GPU は CPU がすでにマイニングしている間にバックグラウンドで起動し、起動中のカードはオンラインになるまで進み具合を表示します。

`CONFIG` には、この実行の設定が表示されます。

- **Pool** はプールのアドレスで、デフォルトは `bntpool.com:3333` です。daemon モードでは `Daemon` とノードの API アドレスが表示されます。
- **Threads** は CPU マイニングスレッドの数です。キー操作が使えるときは、その横に `[+] [-]` が表示されます。**Worker** は、このマシンがプールにログインするときのリグ名です。
- **Tuning** は CPU の自動チューニングを表示します。何を比較していて残り時間がどれくらいかを示し、終わると `done` になります。各状態は [CPU チューニングガイド](/ja/blog/seine-automatic-cpu-tuning/)で説明しています。

プール上でリグを見分けやすい名前にするには、起動時に指定します。

```sh
./seine --pool-worker rig-01
```

`POOL BALANCE` は、数秒ごとに bntpool.com から残高を読み取ります。`Pending` は獲得済みでまだ支払われていない金額で、まだ成熟中のブロックからの推定報酬も含みます。`Paid` はプールがアドレスに送金した金額で、右側の `Miner` は、先頭と末尾の 6 文字に短縮したあなたのアドレスです。アドレスの前に `solo:` を付けてプールでソロマイニングすると、このラベルは `Solo` になります。`Min payout` はプールの最低支払額で、bntpool.com では 1 BNT です。daemon モードではこのパネルは `WALLET` になり、ノードのウォレットの `Pending` と `Unlocked` の残高を表示します。

## ログの読み方

`LOG` には seine の動作が新しいものほど下に並び、各行にタグとどれくらい前に起きたかが付きます。同じ行が繰り返されると `share accepted ×104` のように回数付きの 1 行にまとまるので、長いセッションでもログが読みやすく保たれます。プールでよく見るタグは次のとおりです。

- `CONN`：プールとの接続。例：`connected to pool`
- `SHARE`：`share accepted`、または理由付きの拒否
- `CPU`：チューニングの結果。例：`tuned to 21 threads`
- `BACKEND`：デバイスの起動。例：`cpu: starting 21 threads (~42.0 GiB RAM)`

ログは既定で必要な情報を表示します。内部の設定や、新しいジョブのような定常的な動作も見るには `--verbose` を付けます。

## ダッシュボードではどのキーが使えますか？

<Answer>
Tuning の行が done になったら、+ または = で CPU スレッドを 1 つ増やし、- で 1 つ減らせます。矢印キー、PgUp、PgDn、Home でログをさかのぼってスクロールし、End で再び新しい行を追います。更新のカウントダウン中は、u ですぐにインストールし、s でそのバージョンをスキップします。終了するには q または Ctrl+C を押します。
</Answer>

スレッドの変更は実行中の CPU スレッドにすぐ反映され、GPU とプールとの接続はそのまま動き続けます。チューニングがまだスレッド数を選んでいる間はキーの操作は待機し、ダッシュボードにチューニングの残り時間が表示されます。キー操作はその実行中だけ有効で、次回の起動では再び保存されたチューニング結果を使います。最初から数を固定するには `--threads` を使います。

ログをさかのぼっている間は、ログのタイトルが `LOG  paused, End to follow` になり、`End` を押すまで表示が止まります。

## 小さなターミナルとシンプルな出力

幅が 80 列未満のターミナルでは、3 つの統計パネルが縦に並びます。高さの低いウィンドウでは、seine はコンパクトな表示に切り替わり、ログの上に Threads、State、Current、Average を表示し続けます。デフォルトの `--ui auto` は対話型のターミナルでだけダッシュボードを表示し、`--ui plain` はサーバー、ログファイル、プロセスマネージャー向けのシンプルなスクロール式のログを出力します。

まだ seine をセットアップしていない場合は、[Blocknet のマイニングガイド](/ja/blog/how-to-mine-blocknet/)でダウンロードから最初の受理されたシェアまでを説明しています。
