Ce guide vous montre comment faire passer une ferme de minage Blocknet par un seul proxy de ferme seine. Vous lancez le proxy sur une machine de votre réseau, pointez chaque rig dessus, et le proxy se connecte à bntpool.com pour toute la ferme. Vous réglez le pool, l’adresse de paiement et les pools de secours en un seul endroit et gardez des statistiques par rig sur le pool. Il suit seine v0.3.1.

## Que fait le proxy de ferme ?

<Answer>
Le proxy de ferme, c’est seine qui joue le rôle de pool local pour vos rigs. Il se connecte une fois à bntpool.com pour toute la ferme et donne à chaque rig sa propre part du travail. Le pool voit une seule connexion, chaque rig continue de miner et d’être crédité séparément, et vous changez le pool ou les pools de secours de tous les rigs en un seul endroit.
</Answer>

Un proxy de ferme convient à tous ceux qui font tourner plus d’une poignée de rigs :

- **Un seul endroit pour les réglages.** Réglez le pool, les pools de secours et l’adresse de paiement par défaut sur le proxy, et chaque rig les reprend.
- **Une seule connexion sortante.** Les rigs communiquent avec le proxy sur votre réseau local, et le proxy n’ouvre que les connexions au pool dont la ferme a besoin, en général une ou quelques-unes.
- **Des statistiques par rig sur le pool.** bntpool.com crédite les shares par rig : chaque rig reste donc visible sous son propre nom de worker sur la [page des statistiques](https://bntpool.com/stats).

Le proxy lui-même ne mine pas. Il lui faut peu de CPU et peu de mémoire : il peut donc tourner sur n’importe quelle machine que les rigs peuvent joindre, y compris l’un d’eux.

## Comment lancer le proxy ?

<Answer>
Lancez seine avec --proxy-listen suivi de l’adresse et du port auxquels les rigs se connecteront, ainsi que les options habituelles de pool, d’adresse de paiement et de nom de rig. Par exemple : ./seine --proxy-listen 0.0.0.0:3333 --pool-url stratum+tcp://bntpool.com:3333 --address YOUR_ADDRESS --pool-worker farm-1. Le proxy attend alors les rigs sur le port 3333.
</Answer>

Sur la machine qui fera tourner le proxy :

```bash
./seine --proxy-listen 0.0.0.0:3333 \
        --pool-url stratum+tcp://bntpool.com:3333 \
        --address YOUR_ADDRESS --pool-worker farm-1
```

`--proxy-listen` indique où le proxy accepte les rigs ; `0.0.0.0:3333` écoute sur toutes les interfaces réseau, port 3333. `--address` est l’adresse de paiement par défaut, utilisée pour tout rig qui se connecte sans adresse valide. Toutes les options de pool fonctionnent sur le proxy, y compris les pools de secours : indiquez-les dans l’ordre, séparés par des virgules, et le proxy revient au premier dès qu’il est de nouveau disponible. Le [guide de configuration de seine](https://github.com/zpalmtree/seine/blob/v0.3.1/docs/guides/configuration.md) présente les options de pool.

Liez le proxy à votre réseau local. Toute personne qui peut joindre son port peut miner à travers lui : utilisez donc une adresse du réseau local dans `--proxy-listen`, ou filtrez le port avec un pare-feu, plutôt que de l’exposer à internet.

## Comment pointer les rigs vers le proxy ?

Sur chaque rig, utilisez l’adresse locale du proxy comme pool et donnez au rig son propre nom :

```bash
./seine --pool-url 192.168.1.10:3333 --address YOUR_ADDRESS --pool-worker rig-07
```

Remplacez `192.168.1.10` par l’adresse de la machine du proxy sur votre réseau. Les rigs sous système de minage fonctionnent de la même façon : placez l’adresse du proxy dans le champ d’URL du pool du flight sheet HiveOS ou du profil mmpOS, comme le montre le [guide HiveOS et mmpOS](/fr/blog/mine-blocknet-hiveos-mmpos/). seine enregistre le pool avec les réglages du rig : les démarrages suivants se connectent donc d’eux-mêmes au proxy.

## Comment les rigs derrière le proxy sont-ils payés ?

Chaque rig est payé à l’adresse Blocknet complète avec laquelle il se connecte. Des rigs qui minent vers des portefeuilles différents peuvent partager un proxy, jusqu’à 16 adresses à la fois. Un rig qui se connecte sans adresse, ou avec une adresse invalide, est payé à l’`--address` du proxy.

Quand 16 adresses sont utilisées, un rig avec une 17e adresse attend qu’une des autres soit restée 10 minutes sans rig. Si le pool refuse l’adresse d’un rig, le proxy transmet la raison donnée par le pool, pour que vous puissiez la corriger sur ce rig.

Les rigs derrière le proxy peuvent aussi miner en solo sur bntpool.com : placez `solo:` devant l’adresse du rig, et le pool verse à ce rig la récompense entière de chaque bloc qu’il trouve. [Le minage solo sur bntpool.com](https://bntpool.com/blog/fr/solo-mine-blocknet-on-bntpool/) explique les récompenses solo. Les paiements vers une plateforme d’échange nécessitent un mémo de dépôt, que le proxy ne transmet pas : connectez donc ces rigs directement au pool.

## Comment suivre la ferme ?

Sur bntpool.com, recherchez chaque adresse de paiement sur la [page des statistiques](https://bntpool.com/stats). Chaque rig derrière le proxy apparaît dans le tableau Workers sous son propre nom de rig, avec son hashrate, ses shares et l’heure de son dernier share, exactement comme avec des connexions directes. Le [guide de suivi du mineur](https://bntpool.com/blog/fr/track-your-miner-on-bntpool/) présente la page.

Le proxy journalise aussi son propre résumé chaque minute : rigs connectés, shares acceptés et rejetés, hashrate estimé et connexions au pool. Il journalise chaque rig qui se connecte ou se déconnecte, ce qui vous permet de voir d’un coup d’œil quand un rig décroche. Le tableau de bord seine de chaque rig affiche toujours son hashrate et ses shares locaux, comme l’explique le [guide du tableau de bord](/fr/blog/seine-dashboard-explained/).

## Que faut-il savoir d’autre ?

- **Les connexions au pool augmentent avec la ferme.** Le proxy ouvre autant de connexions au pool que la ferme en a besoin pour que chaque rig reçoive du travail à chaque nouveau bloc. Pour la plupart des fermes, c’est une ou quelques-unes, et les très grandes fermes montent jusqu’à 64 par adresse de paiement.
- **Chaque rig garde ses propres réglages.** Le nombre de threads, le choix des GPU et le réglage restent sur le rig. Le [guide des réglages](/fr/blog/configure-seine-miner/) les présente, et le [guide du minage sur serveur](/fr/blog/mine-blocknet-on-servers/) traite des gros serveurs CPU.
- **Mises à niveau du réseau.** Lors de la mise à niveau réseau Faraday, le proxy demande aux rigs dont la version de seine ne la prend pas en charge de se mettre à jour, comme le fait le pool.
