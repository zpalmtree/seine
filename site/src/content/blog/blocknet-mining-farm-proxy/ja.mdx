各リグがそれぞれプールに接続していると、プールを変更するたびにすべてのリグで作業が必要になります。seineのファームプロキシを使うと、リグはネットワーク上の1台のマシンに接続し、そのマシンがファーム全体のためにbntpool.comへ接続します。プール、バックアッププール、既定の支払いアドレスは一度変更するだけで、すべてのリグがそれに従います。各リグは引き続きbntpool.comにそれぞれの名前で表示されます。内容はseine v0.3.1に基づいています。

## ファームプロキシで何ができますか？

<Answer>
ファームプロキシは、リグ向けのローカルプールとして動くseineです。ファーム全体のためにbntpool.comへ接続し、各リグに作業のうちそれぞれの分を渡します。プール、バックアッププール、既定の支払いアドレスは1か所で管理でき、各リグはそれぞれマイニングして個別に計上されます。
</Answer>

ファームをプロキシ経由で動かすと、次のことが変わります。

- **1回の再起動でファーム全体のプールを切り替え。** プールとバックアッププールはプロキシにあるので、すべてのリグ、flight sheet、プロファイルではなく、コマンドラインを1つ編集するだけです。
- **すべてのリグのフェイルオーバーを一度に。** プロキシにバックアッププールを並べておくと、ファーム全体がそろって次のプールへ移り、最初のプールが応答するようになるとそこへ戻ります。
- **リグの追加は1行。** 新しいリグに必要なのは、プールとしてプロキシのアドレスを指定することだけです。ファームのほかの部分は何も変わりません。
- **インターネットと通信するのは1台だけ。** リグはローカルネットワークでプロキシと通信し、プールに届く必要があるのはプロキシだけです。ファイアウォールのルール1つでファーム全体をカバーでき、マイニング用ポートを遮断するネットワーク向けのSOCKS5プロキシもプロキシにだけ設定します。
- **各リグの統計はそのまま。** bntpool.comはリグごとにシェアを計上するので、各リグは[統計ページ](https://bntpool.com/stats?lang=ja)にそれぞれのワーカー名、ハッシュレート、シェアで表示されます。
- **1つのプロキシで複数のウォレット。** 各リグはログインに使ったアドレスへ支払われるので、友人やパートナーのために動かすリグなど、最大16の異なるウォレットのリグを1つのプロキシで扱えます。

プロキシ自体はマイニングしません。CPUもメモリもほとんど使わないので、小さなサーバーでも、リグの1台でそのリグのマイナーと並べてでも動かせます。

## ファームプロキシはどう設定しますか？

<Answer>
--proxy-listenにリグが接続するアドレスとポートを指定し、いつものプール、支払いアドレス、リグ名のオプションも加えてseineを起動します。例：./seine --proxy-listen 0.0.0.0:3333 --pool-url stratum+tcp://bntpool.com:3333 --address YOUR_ADDRESS --pool-worker farm-1。そのあと、各リグのプールURLをプロキシに向けます。
</Answer>

設定は2ステップです。プロキシを起動し、リグをそこに向けます。

**1. プロキシを起動します。** プロキシを動かすマシンで次を実行します。

```bash
./seine --proxy-listen 0.0.0.0:3333 \
        --pool-url stratum+tcp://bntpool.com:3333 \
        --address YOUR_ADDRESS --pool-worker farm-1
```

`--proxy-listen`はプロキシがリグを受け付ける場所を設定します。`0.0.0.0:3333`はすべてのネットワークインターフェースのポート3333で待ち受けます。`--address`は既定の支払いアドレスで、有効なアドレスなしでログインしたリグに使われます。プールのオプションはすべてプロキシで使えます。バックアッププールはカンマで区切って順に並べ、プールに届くのにSOCKS5プロキシが必要なネットワークでは`--pool-proxy socks5://host:port`を加えます。プールのオプションは[seineの設定ガイド](https://github.com/zpalmtree/seine/blob/v0.3.1/docs/guides/configuration.md)で説明しています。

プロキシはローカルネットワーク内に置いてください。`--proxy-listen`にLANのアドレスを使うか、ポートをファイアウォールで保護すれば、自分のリグだけがプロキシ経由でマイニングし、あなたのアドレスに支払えます。

**2. 各リグをプロキシに向けます。** プロキシのローカルアドレスをプールとして指定し、リグに固有の名前を付けます。

```bash
./seine --pool-url 192.168.1.10:3333 --address YOUR_ADDRESS --pool-worker rig-07
```

`192.168.1.10`は、ネットワーク上のプロキシマシンのアドレスに置き換えてください。マイニングOSでは、[HiveOSとmmpOSのガイド](/ja/blog/mine-blocknet-hiveos-mmpos/)のとおり、HiveOSのflight sheetやmmpOSのプロファイルのプールURL欄にプロキシのアドレスを入れます。seineはプールをリグの設定と一緒に保存するので、次回以降は自動でプロキシに接続し、それ以降のプール管理はプロキシで行います。

## プロキシの後ろのリグはどのように支払われますか？

各リグは、直接接続のときとまったく同じように、ログインに使った完全なBlocknetアドレスへ支払われます。別々のウォレットへマイニングするリグも1つのプロキシを共有でき、同時に最大16アドレスまで使えます。アドレスなし、または無効なアドレスでログインしたリグは、プロキシの`--address`へ支払われるので、そのハッシュレートも引き続きあなたのものになります。

16のアドレスが使われているときは、17番目のアドレスを持つリグは、ほかのアドレスのどれかでリグが10分間なくなるまで待ちます。プールがリグのアドレスを拒否した場合、プロキシはプールの理由をそのまま伝えるので、そのリグで修正できます。

プロキシの後ろのリグもbntpool.comでソロマイニングできます。リグのアドレスの前に`solo:`を付けると、プールはそのリグが見つけた各ブロックの全報酬をそのリグに支払います。ソロの報酬は[bntpool.comでのソロマイニング](https://bntpool.com/blog/ja/solo-mine-blocknet-on-bntpool/)で説明しています。取引所への支払いには入金メモを使いますが、プロキシはメモを中継しないので、取引所へ支払うリグはプールに直接接続してください。

## ファームの状況はどう確認しますか？

bntpool.comの[統計ページ](https://bntpool.com/stats?lang=ja)で、各支払いアドレスを検索します。プロキシの後ろのすべてのリグが、直接接続と同じように、Workersの表にそれぞれのリグ名、ハッシュレート、シェア、最後のシェアの時刻とともに表示されます。ページの見方は[マイナー追跡ガイド](https://bntpool.com/blog/ja/track-your-miner-on-bntpool/)で説明しています。

プロキシは、ファーム全体を見渡せる独自の情報も加えます。1分ごとに概要をログに記録します。接続中のリグ、受理・拒否されたシェア、ファーム全体の推定ハッシュレート、プール接続です。リグの接続と切断もそのつど記録するので、リグが外れたときは1つのログでわかります。各リグのseineダッシュボードには、[ダッシュボードガイド](/ja/blog/seine-dashboard-explained/)で説明しているとおり、引き続きローカルのハッシュレートとシェアが表示されます。

## ファームが大きくなってもプロキシは対応できますか？

はい。プロキシは、新しいブロックのたびにすべてのリグが作業を受け取れるだけのプール接続を開きます。ほとんどのファームでは1つか数本で、非常に大きなファームでは支払いアドレスごとに最大64本になります。これを設定する必要はなく、リグが加わるとプロキシが接続を追加します。

ほかにも、直接マイニングからそのまま引き継がれる点があります。

- **各リグは自分のチューニングを保ちます。** スレッド数、GPUの選択、チューニングはリグ側に残ります。これらは[設定ガイド](/ja/blog/configure-seine-miner/)で、大規模なCPUサーバーは[サーバーマイニングガイド](/ja/blog/mine-blocknet-on-servers/)で説明しています。
- **ネットワークアップグレード。** Faradayネットワークアップグレードの際には、プロキシは対応していないseineリリースのリグに、プールと同じように更新を求めます。
