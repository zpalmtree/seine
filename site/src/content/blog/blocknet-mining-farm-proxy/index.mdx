When every rig connects to the pool on its own, every pool change is a job on every rig. With the seine farm proxy, your rigs connect to one machine on your network, and that machine connects to bntpool.com for the whole farm. You change the pool, backup pools or default payout address once, and every rig follows. Each rig still shows on bntpool.com under its own name. This guide follows seine v0.3.1.

## What does the farm proxy do for you?

<Answer>
The farm proxy is seine running as a local pool for your rigs. It connects to bntpool.com for the whole farm and hands each rig its own share of the work. You manage pools, backup pools and the default payout address in one place, while each rig still mines and is credited on its own.
</Answer>

Here is what changes once the farm runs through a proxy:

- **Switch pools for the whole farm with one restart.** The pool and backup pools live on the proxy, so you edit one command line instead of every rig, flight sheet or profile.
- **Failover for every rig at once.** List backup pools on the proxy and the whole farm moves to the next pool together, then back to the first when it answers again.
- **Add a rig in one line.** A new rig only needs the proxy's address as its pool. Nothing else on the farm changes.
- **One machine talks to the internet.** Rigs talk to the proxy over your local network, and only the proxy needs to reach the pool. One firewall rule covers the farm, and a SOCKS5 proxy for networks that block mining ports goes on the proxy alone.
- **Every rig still has its own stats.** bntpool.com credits shares per rig, so each rig shows on the [stats page](https://bntpool.com/stats) under its own worker name, with its own hashrate and shares.
- **Several wallets on one proxy.** Each rig is paid to the address it logs in with, so one proxy can serve rigs for up to 16 different wallets, such as rigs you run for friends or partners.

The proxy itself doesn't mine. It needs little CPU or memory, so it can run on a small server or on one of the rigs, next to that rig's own miner.

## How do you set up the farm proxy?

<Answer>
Start seine with --proxy-listen and the address and port the rigs will connect to, plus the usual pool, payout address and rig name options. For example: ./seine --proxy-listen 0.0.0.0:3333 --pool-url stratum+tcp://bntpool.com:3333 --address YOUR_ADDRESS --pool-worker farm-1. Then point each rig's pool URL at the proxy.
</Answer>

Setup takes two steps: start the proxy, then point the rigs at it.

**1. Start the proxy** on the machine that will run it:

```bash
./seine --proxy-listen 0.0.0.0:3333 \
        --pool-url stratum+tcp://bntpool.com:3333 \
        --address YOUR_ADDRESS --pool-worker farm-1
```

`--proxy-listen` sets where the proxy accepts rigs; `0.0.0.0:3333` listens on every network interface on port 3333. `--address` is the default payout address, used for any rig that logs in without a valid one. Every pool option works on the proxy. For backup pools, list them in order, separated by commas, and add `--pool-proxy socks5://host:port` if your network needs a SOCKS5 proxy to reach the pool. The [seine configuration guide](https://github.com/zpalmtree/seine/blob/v0.3.1/docs/guides/configuration.md) covers the pool options.

Keep the proxy on your local network: use a LAN address in `--proxy-listen`, or firewall the port, so only your own rigs can mine through it and pay your address.

**2. Point each rig at the proxy**, using the proxy's local address as the pool and giving the rig its own name:

```bash
./seine --pool-url 192.168.1.10:3333 --address YOUR_ADDRESS --pool-worker rig-07
```

Replace `192.168.1.10` with the proxy machine's address on your network. On a mining OS, put the proxy's address in the pool URL field of the HiveOS flight sheet or mmpOS profile, as the [HiveOS and mmpOS guide](/blog/mine-blocknet-hiveos-mmpos/) shows. Seine saves the pool with the rig's settings, so later starts connect to the proxy by themselves, and from then on you manage pools on the proxy.

## How are rigs behind the proxy paid?

Each rig is paid to the full Blocknet address it logs in with, exactly as with a direct connection. Rigs that mine to different wallets can share one proxy, up to 16 addresses at a time. A rig that logs in with no address, or an invalid one, is paid to the proxy's `--address`, so its hashrate still goes to you.

When 16 addresses are in use, a rig with a 17th address waits until one of the others has had no rigs for 10 minutes. If the pool refuses a rig's address, the proxy passes on the pool's reason, so you can fix it on that rig.

Rigs behind the proxy can mine solo on bntpool.com too: put `solo:` in front of the rig's address, and the pool pays that rig the whole reward of each block it finds. [Solo mining on bntpool.com](https://bntpool.com/blog/solo-mine-blocknet-on-bntpool/) explains solo rewards. Exchange payouts use a deposit memo, which the proxy doesn't carry, so connect rigs that pay an exchange to the pool directly.

## How do you follow the farm?

On bntpool.com, look up each payout address on the [stats page](https://bntpool.com/stats). Every rig behind the proxy appears in the Workers table under its own rig name, with its hashrate, shares and last-share time, exactly as with direct connections. The [miner tracking guide](https://bntpool.com/blog/track-your-miner-on-bntpool/) explains the page.

The proxy adds a farm-wide view of its own. Every minute it logs a summary: connected rigs, accepted and rejected shares, an estimated hashrate for the farm and its pool connections. It also logs each rig as it connects and disconnects, so one log shows when a rig drops off. Each rig's own seine dashboard still shows its local hashrate and shares, as the [dashboard guide](/blog/seine-dashboard-explained/) explains.

## Does the proxy keep up as the farm grows?

Yes. The proxy opens as many pool connections as the farm needs for every rig to get work on each new block. For most farms that is one or a few, and very large farms get up to 64 per payout address. You don't set this; the proxy adds connections as rigs join.

A few more things carry over from direct mining unchanged:

- **Each rig keeps its own tuning.** Thread counts, GPU selection and tuning stay on the rig. The [settings guide](/blog/configure-seine-miner/) covers them, and the [server mining guide](/blog/mine-blocknet-on-servers/) covers large CPU servers.
- **Network upgrades.** At the Faraday network upgrade, the proxy asks rigs on a seine release without support for it to update, the same way the pool does.
