Seine mines Blocknet on your NVIDIA GPU alongside the CPU. This guide covers Windows and Linux setup, card selection, accepted shares and a measured RTX 5090 comparison. The commands describe seine v0.3.0 and the current Argon2id network as of October 2026.

## How do you start mining Blocknet with an NVIDIA GPU?

<Answer>
Download the Windows x86_64 or Linux x86_64 seine archive, prepare the NVIDIA driver and runtime libraries for your platform, and run the miner. Enter your payout address and accept the default pool. Seine selects the CPU and detected NVIDIA cards automatically, then prepares and tunes each GPU backend.
</Answer>

Choose your archive in the [download section](/#download): `seine-windows-x86_64.zip` for Windows or `seine-linux-x86_64.tar.gz` for Linux x86_64. The [general mining guide](/blog/how-to-mine-blocknet/) covers getting a payout address and making your first connection.

Start with the defaults. Leave the kernel, register cap, GPU lane count and CPU thread count unset so seine can choose its configuration. The Devices panel shows which backends are contributing once initialization finishes.

## Set up the NVIDIA runtime on Windows or Linux

| Platform | What to prepare | Start command |
|---|---|---|
| Windows x86_64 | NVIDIA display driver; bundled runtime DLLs beside the executable | `.\seine.exe` |
| Linux x86_64 | NVIDIA driver | `./seine` |

On Windows, extract the complete ZIP into a writable folder. Keep `nvrtc64_120_0.dll` and `nvrtc-builtins64_128.dll` beside `seine.exe`. The packaged release uses these bundled libraries; a separate CUDA Toolkit installation is not required.

![The Windows archive in the official seine download table](/assets/blog/windows-download.png)

Install the driver for your card and operating system from [NVIDIA's driver page](https://www.nvidia.com/en-us/drivers/). The [Windows setup guide](/blog/mine-blocknet-on-windows/) walks through the download, checksum and extraction.

On Linux, the NVIDIA driver is all you need. Seine uses NVRTC when it is installed and otherwise loads the kernels built into seine, which cover GeForce GTX 10 series and newer cards. The [seine NVIDIA requirements](https://github.com/zpalmtree/seine/blob/master/docs/guides/nvidia.md) have the details.

Launch the binary from its folder. Reuse the same working directory to keep your saved settings in `seine-data`. On a first launch, enter your receiving address and accept `stratum+tcp://bntpool.com:3333` for the pool.

## Can you select one NVIDIA card and keep CPU mining?

Select both backends and the device index. In PowerShell, this keeps CPU mining and selects NVIDIA device `0`:

```powershell
.\seine.exe --backend cpu,nvidia --nvidia-devices 0
```

Use the same options with the Linux executable:

```bash
./seine --backend cpu,nvidia --nvidia-devices 0
```

These commands use your saved address and pool or ask for them at startup. To supply the connection explicitly, add your public receiving address with `--address` and the pool URL with `--pool-url`.

The index identifies a GPU enumerated by the NVIDIA runtime. Confirm the device list after startup. `--nvidia-devices 0,1` selects those two cards; omitting the selector uses all detected NVIDIA devices.

For GPU-only mining, select `nvidia`:

```bash
./seine --backend nvidia
```

In PowerShell, use `.\seine.exe --backend nvidia`. Include `cpu` in the backend list when you want both types of hardware. Restart seine with the desired command when changing that selection.

## How do you confirm the GPU is mining?

<Answer>
Look at the Devices panel for NVIDIA backend rows and their current and average hashrates. During initialization, a row can show startup progress while CUDA kernels are prepared. Once hashing begins, check the log for share events from that backend and the Mining panel for accepted shares.
</Answer>

NVIDIA backends appear as `nvidia#1`, `nvidia#2` and so on; the CPU has its own row. The overall hashrate includes all active backends. The [dashboard guide](/blog/seine-dashboard-explained/) explains the remaining panels and log labels.

The first launch prepares and tunes the GPU kernels. Seine saves NVIDIA autotune results in `seine-data/seine.nvidia-autotune.json`. Reuse that data directory so later launches can load compatible saved results, or select a directory explicitly with `--data-dir`.

## What should you check if an NVIDIA row is missing?

Check the driver first. On Windows, also keep the bundled NVRTC DLLs beside `seine.exe`. On Linux, install the NVIDIA driver in the environment where you launch the miner.

Then check your command. `--backend cpu` selects only the CPU. Use the default command or `--backend cpu,nvidia` for both. If you set `--nvidia-devices`, verify the indices exist on your machine.

Read the startup log for that backend: it distinguishes ongoing preparation from an initialization error. Correct the reported runtime or selection issue and restart. The [NVIDIA guide](https://github.com/zpalmtree/seine/blob/master/docs/guides/nvidia.md) also covers source-build requirements.

For the current Argon2id workload, each active GPU lane needs a 2 GiB arena plus runtime overhead. Seine sizes GPU work using available device memory and allocation checks. Leave lane overrides unset; advertised VRAM alone does not determine how many lanes are available during a desktop session.

If the device is hashing but the pool shows zero, follow the [pool hashrate checklist](https://bntpool.com/blog/track-your-miner-on-bntpool/#zero-hashrate) for address, connection and accepted-share checks.
