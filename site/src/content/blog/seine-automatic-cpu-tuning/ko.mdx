채굴 중 seine의 CPU 스레드 수가 바뀔 때 seine이 무엇을 하는지 알아봅니다. 이 가이드는 공개 버전 v0.3.1을 기준으로 seine이 CPU에 가장 빠른 설정을 찾는 방법, 그 속도에 도달하는 가장 적은 스레드 수를 유지하는 이유, 다시 확인하는 시점을 설명합니다. 설치는 [채굴 가이드](/ko/blog/how-to-mine-blocknet/)부터 시작하고, 각 패널의 의미는 [대시보드 둘러보기](/ko/blog/seine-dashboard-explained/)를 참고하세요.

## CPU 자동 튜닝은 어떻게 작동하나요?

<Answer>
seine은 바로 채굴을 시작하고 실제 채굴 작업으로 튜닝합니다. 프로세서가 실행할 수 있는 CPU 커널을 먼저 비교한 뒤 스레드 수를 비교하며, 현재 설정, 후보, 다시 현재 설정 순으로 측정합니다. 가장 빠른 설정만큼 빠르게 해시를 계산하는 가장 적은 스레드 수를 유지하고, 무언가 바뀔 때까지 테스트를 멈춥니다.
</Answer>

<img src="/assets/blog/cpu-autotuning.svg" alt="기준–후보–기준 비교를 반복해 설정을 저장하며 과정 내내 가용 메모리를 확인합니다." width="1200" height="675" loading="lazy" />

자동 튜닝을 사용하려면 `--threads`를 지정하지 마세요. 설정할 것은 없습니다. seine은 알고 있는 가장 좋은 시작점에서 출발합니다. 이 컴퓨터의 저장된 결과, 그다음 CPU 모델별 시작점, 마지막으로 코어 수와 여유 RAM에 따른 추정치입니다. 거기서부터 스레드를 더 늘려도 도움이 되지 않을 때까지 간격을 넓혀 가며 찾은 뒤 범위를 좁힙니다.

각 후보의 앞뒤로 현재 설정을 실행하므로, 브라우저 탭이나 백그라운드 업데이트 같은 부하 변화가 후보에게 유리하거나 불리하게 작용하지 않습니다. 확실히 느린 후보는 중간에 끊으므로 대부분의 컴퓨터는 몇 분 안에 끝납니다.

## 대시보드의 Tuning 행은 무엇을 뜻하나요?

대시보드의 `Tuning:` 행은 튜닝 상태를 알려 줍니다.

| 행 | 의미 |
|---|---|
| `trying kernels, about 4 min left` | 채굴하면서 CPU 커널을 비교하는 중 |
| `12 vs 16 threads, about 3 min left` | 두 스레드 수를 비교하는 중이며, 측정하는 동안 수가 둘 사이를 오갑니다 |
| `update: 12 vs 14 threads, ~2 min` | CPU 관련 변경이 있는 새 버전이 그 부분만 테스트하는 중 |
| `done` | 튜닝 완료. 무언가 바뀌지 않는 한 스레드 수가 유지됩니다 |
| `low on RAM, best is 12 threads` | RAM이 다시 여유로워질 때까지 스레드를 줄여 실행하는 중 |

로그에는 튜닝을 시작할 때 이유를 알려 주는 한 줄과 끝났을 때의 한 줄이 남습니다. 예를 들면 `tuned to 12 threads`입니다. 다른 패널은 [대시보드 가이드](/ko/blog/seine-dashboard-explained/)에서 설명합니다.

## seine은 왜 가능한 것보다 적은 스레드를 사용하나요?

각 CPU 스레드는 큰 메모리 영역을 사용하고, 모든 스레드가 컴퓨터의 메모리 대역폭을 공유합니다. 일정 수를 넘으면 스레드를 늘려도 해시레이트가 오르지 않고, 다른 프로그램이 쓸 수 있는 RAM만 차지합니다. 그래서 seine은 가장 빠른 수와 같은 속도를 내는 수를 모두 똑같이 좋은 것으로 보고, 그중 가장 적은 수를 유지합니다. 같은 해시레이트를 얻으면서 메모리는 더 많이 남습니다.

그래서 최적의 수는 코어 수나 전체 스레드 수보다 적은 경우가 많고, 비슷해 보이는 컴퓨터끼리도 다릅니다. 스레드 수, 메모리 채널, 페이지 할당이 모두 영향을 주므로 다른 컴퓨터의 결과는 참고 자료일 뿐 그대로 복사할 설정이 아닙니다. 스레드당 메모리 예산은 [RAM 가이드](/ko/blog/how-much-ram-to-mine-blocknet/)에서 설명합니다.

마지막 몇 해시보다 전력과 메모리 절약을 원한다면 `--cpu-profile efficiency`로 가장 빠른 수에 가까운 더 적은 스레드 수를 유지할 수 있습니다.

## seine은 CPU 커널도 튜닝하나요?

네. 여기서 커널은 특정 프로세서 명령어 세트에 맞춘 해시의 소프트웨어 구현입니다. seine은 CPU가 지원하는 명령어를 확인하고, 실행할 수 없는 커널은 시도하지 않으며, 해당 CPU에서 이기지 못하는 커널은 건너뜁니다. 나머지는 채굴하면서 비교한 뒤 스레드 수를 정합니다. 커널 전환은 해시와 해시 사이에 이루어지므로 채굴은 계속되고 풀 연결도 유지됩니다.

## seine은 언제 다시 튜닝하나요?

행이 `done`이 되면 seine은 예정된 테스트를 하지 않습니다. 무언가 바뀌었을 때만 다시 확인합니다.

- **새 버전이 CPU 관련 부분을 바꿨을 때.** 새 릴리스는 저장된 결과에서 시작해 새 커널이나 개선된 커널처럼 바뀐 부분만 테스트합니다. 해시 계산에 관한 변경이 없는 버전은 테스트를 전혀 하지 않습니다.
- **해시레이트가 한동안 계속 달라졌을 때.** 예를 들어 다른 프로그램이 CPU를 많이 쓰기 시작하거나 그만둘 때입니다.
- **RAM 부족으로 스레드 수가 제한되었다가 여유 RAM이 늘었을 때.**
- **하드웨어, 운영체제 또는 CPU 제한이 바뀌었을 때.** 컨테이너의 CPU 제한 같은 경우입니다.

어느 경우든 튜닝을 시작한 이유가 로그에 한 줄로 기록됩니다. 자동 업데이트는 튜닝 결과를 유지하므로 seine을 업데이트해도 처음부터 다시 시작하지 않습니다. 업데이트 방식은 [업데이트 가이드](/ko/blog/update-seine-miner/)에서 설명합니다.

## 다른 프로그램이 RAM을 필요로 하면 어떻게 되나요?

seine은 1초마다 여유 RAM을 확인합니다. 다른 프로그램이 메모리를 필요로 하면 CPU 스레드는 계산 중인 해시를 마친 뒤 대기하며 메모리 영역을 해제하고, 행에는 `low on RAM`이 표시됩니다. 메모리가 다시 여유로워지면 스레드가 돌아옵니다. 학습한 최적의 수는 저장된 채로 남으므로 잠깐의 메모리 부족으로 지워지지 않습니다.

Linux에서는 해제된 명시적 HugeTLB 영역이 예약된 휴즈 페이지 풀로 돌아가며, seine은 그 풀의 크기를 바꾸지 않습니다. 휴즈 페이지 예약은 [휴즈 페이지 가이드](/ko/blog/huge-pages-blocknet-mining/)에서 다룹니다.

## 저장된 튜닝 결과는 어떻게 재사용되나요?

결과는 데이터 디렉터리(기본값 `seine-data`)의 `seine.cpu-autotune.json`에 저장됩니다. 다음 시작 때 seine은 저장된 결과로 바로 돌아가고 행은 `done`으로 표시됩니다. 해시레이트가 지난번과 확실히 다르면 다시 튜닝하고 로그에 이유를 남깁니다. seine이 파일을 찾을 수 있도록 실행 사이에 같은 데이터 디렉터리를 유지하고, 장비마다 각자의 파일을 만들게 하세요. 결과는 정확한 하드웨어와 설정에 따라 달라지므로 다른 컴퓨터의 파일을 복사해도 도움이 되지 않습니다.

## 스레드 수를 직접 바꿀 수 있나요?

네. 대시보드에서 `-` 또는 `+`를 누르면 CPU 스레드를 하나 줄이거나 늘립니다. 튜닝이 `done`이면 변경은 실행 중인 스레드에 바로 적용되며, GPU와 풀 연결은 계속 동작합니다. 튜닝이 아직 스레드 수를 고르는 중이면 키 입력은 대기하고 대시보드에 튜닝의 남은 시간이 표시됩니다. 키 입력은 해당 실행에만 적용되며, 다음 시작 때는 다시 저장된 결과를 사용합니다.

처음부터 수를 고정하려면 `--threads`를 사용하세요. 예를 들면 `--threads 4`입니다. 그러면 seine은 그 수를 유지하면서도 그 수에 가장 좋은 커널을 고릅니다. `--disable-cpu-autotune-threads`는 스레드와 커널 튜닝을 모두 끕니다. 이 옵션들은 [플래그 참조](https://github.com/zpalmtree/seine/blob/v0.3.1/docs/MINER_FLAGS.md)에 정리되어 있으며, [PC를 사용하면서 채굴하기](/ko/blog/mine-while-using-pc/)에서 데스크톱을 쓰면서 채굴하는 방법을 보여 줍니다.

평소 채굴은 기본 설정으로 시작하고 튜닝이 `done`에 이를 때까지 두세요. 튜닝 시도는 CPU 장치 행에서, 적립된 채굴 활동은 [풀 통계](https://bntpool.com/blog/ko/track-your-miner-on-bntpool/)에서 확인할 수 있습니다.
