了解 seine 在挖矿过程中改变 CPU 线程数时在做什么。本指南依据公开版本 v0.3.1，说明 seine 如何为你的 CPU 找到最快的设置、为什么保留达到该速度的最少线程数，以及何时会重新检查。安装请从[挖矿指南](/zh-hans/blog/how-to-mine-blocknet/)开始；各面板的含义请参阅[仪表盘介绍](/zh-hans/blog/seine-dashboard-explained/)。

## CPU 自动调优如何工作？

<Answer>
seine 会立即开始挖矿，并在真实的挖矿工作中进行调优。它先比较你的处理器能运行的 CPU 计算内核，再比较线程数，依次测量当前设置、候选设置，然后再测一次当前设置。它保留与最佳设置一样快的最少线程数，之后停止测试，直到情况发生变化。
</Answer>

<img src="/assets/blog/cpu-autotuning.svg" alt="重复进行基准—候选—基准比较并保存选择，全程检查可用内存。" width="1200" height="675" loading="lazy" />

不设置 `--threads` 即可使用自动调优，无需任何配置。seine 从它所知的最佳起点开始：先是这台机器保存的结果，其次是针对你的 CPU 型号的起点，最后是根据核心数和可用内存得出的估计值。然后它以逐步增大的步长搜索，直到增加线程不再有帮助，再逐步缩小范围。

在每个候选设置前后都运行当前设置，意味着负载变化（例如浏览器标签页或后台更新）不会让候选设置占便宜或吃亏。明显更慢的候选会被提前终止，所以大多数机器几分钟内就能完成。

## 仪表盘上的 Tuning 行是什么意思？

仪表盘的 `Tuning:` 行显示调优进行到哪一步：

| 行 | 含义 |
|---|---|
| `trying kernels, about 4 min left` | 一边挖矿一边比较 CPU 计算内核 |
| `12 vs 16 threads, about 3 min left` | 正在比较两个线程数；测量期间线程数在两者之间切换 |
| `update: 12 vs 14 threads, ~2 min` | 新版本对你的 CPU 做了改动，只测试改动的部分 |
| `done` | 调优完成。除非情况发生变化，线程数保持不变 |
| `low on RAM, best is 12 threads` | 减少线程运行，直到内存再次空闲 |

日志会在调优开始时写一行说明原因，结束时再写一行，例如 `tuned to 12 threads`。[仪表盘指南](/zh-hans/blog/seine-dashboard-explained/)介绍了其他面板。

## 为什么 seine 使用的线程比它能用的少？

每个 CPU 线程占用一大块内存区域，所有线程共享机器的内存带宽。超过一定数量后，增加线程不会提高算力，反而会占用其他程序可以使用的内存。因此，seine 把所有与最快速度相同的线程数都视为同样好，并保留其中最少的一个。你得到同样的算力，同时留出更多空闲内存。

这就是为什么最佳线程数常常低于核心数或线程总数，而且看起来相似的机器之间也会不同。线程数、内存通道和内存页分配都会产生影响，所以另一台电脑的结果只能作为参考，不能直接照搬。[内存指南](/zh-hans/blog/how-much-ram-to-mine-blocknet/)介绍了每个线程的内存需求。

如果你更看重节省电力和内存，而不是最后那一点算力，`--cpu-profile efficiency` 会保留一个接近最快速度的较少线程数。

## seine 也会调优 CPU 计算内核吗？

会。这里的计算内核是指针对某一组处理器指令实现哈希算法的软件代码。seine 会检查你的 CPU 支持哪些指令，绝不尝试无法运行的计算内核，并跳过在你的 CPU 上不占优势的计算内核。其余的会在挖矿时比较，然后再确定线程数。计算内核的切换发生在完整的哈希之间，所以挖矿不会中断，矿池连接也保持不变。

## seine 什么时候会重新调优？

Tuning 行显示 `done` 后，seine 不再进行定期测试。只有当情况发生变化时，它才会重新检查：

- **新版本对你的 CPU 做了改动。** 新版本从你保存的结果开始，只测试改动的部分，例如新的或改进的计算内核。没有改动哈希计算的版本完全不做测试。
- **算力持续一段时间发生变化，** 例如另一个程序开始或停止大量使用 CPU。
- **之前因内存不足限制了线程数，之后有更多内存空闲。**
- **硬件、操作系统或 CPU 限制发生变化，** 例如容器的 CPU 限制。

每种情况都会在日志中写一行，说明调优开始的原因。自动更新会保留你的调优结果，所以更新 seine 不会让调优从头开始。[更新指南](/zh-hans/blog/update-seine-miner/)介绍了更新的工作方式。

## 其他程序需要内存时会怎样？

seine 每秒检查一次可用内存。当其他程序需要内存时，CPU 线程会算完当前的哈希，然后暂停并释放各自的内存区域，Tuning 行显示 `low on RAM`。内存再次空闲后，线程会恢复。它学到的最佳线程数仍然保存着，所以短暂的内存紧张不会抹掉它。

在 Linux 上，释放的显式 HugeTLB 内存区域会回到预留的大页内存池；seine 不会调整该内存池的大小。[大页指南](/zh-hans/blog/huge-pages-blocknet-mining/)介绍了如何预留大页。

## 保存的调优结果如何复用？

结果保存在数据目录（默认为 `seine-data`）中的 `seine.cpu-autotune.json`。下次启动时，seine 会直接恢复保存的结果，Tuning 行显示 `done`。如果算力与上次明显不同，它会重新调优，并在日志中说明原因。请在多次运行之间保持同一个数据目录，让 seine 能找到这个文件，并让每台矿机生成自己的文件：复制另一台机器的文件没有帮助，因为结果取决于具体的硬件和设置。

## 可以自己修改线程数吗？

可以。在仪表盘中按 `-` 或 `+` 可以减少或增加一个 CPU 线程。调优显示 `done` 后，修改会立即作用于正在运行的线程，GPU 和矿池连接继续运行。调优仍在选择线程数时，按键会等待，仪表盘会显示调优还剩多少时间。按键调整只对本次运行有效；下次启动会再次使用保存的结果。

要从一开始就固定线程数，使用 `--threads`，例如 `--threads 4`。seine 会保持该线程数，同时仍为它选择最佳计算内核。`--disable-cpu-autotune-threads` 会完全关闭线程和计算内核的调优。[参数参考](https://github.com/zpalmtree/seine/blob/v0.3.1/docs/MINER_FLAGS.md)记录了这些选项，[边用电脑边挖矿](/zh-hans/blog/mine-while-using-pc/)介绍了如何在使用台式机的同时挖矿。

日常挖矿请从默认设置开始，让调优达到 `done`。用 CPU 设备行跟踪调优试验，用[矿池统计](https://bntpool.com/blog/zh-hans/track-your-miner-on-bntpool/)跟踪已计入的挖矿活动。
