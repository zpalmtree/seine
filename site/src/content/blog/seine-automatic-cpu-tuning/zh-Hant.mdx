了解 seine 在挖礦過程中改變 CPU 執行緒數時在做什麼。本指南依據公開版本 v0.3.1，說明 seine 如何為你的 CPU 找到最快的設定、為什麼保留達到該速度的最少執行緒數，以及何時會重新檢查。安裝請從[挖礦指南](/zh-hant/blog/how-to-mine-blocknet/)開始；各面板的含義請參閱[儀表板介紹](/zh-hant/blog/seine-dashboard-explained/)。

## CPU 自動調校如何運作？

<Answer>
seine 會立即開始挖礦，並在真實的挖礦工作中進行調校。它先比較你的處理器能執行的 CPU 運算核心程式，再比較執行緒數，依序測量目前設定、候選設定，然後再測一次目前設定。它保留與最佳設定一樣快的最少執行緒數，之後停止測試，直到情況發生變化。
</Answer>

<img src="/assets/blog/cpu-autotuning.svg" alt="重複進行基準—候選—基準比較並儲存選擇，全程檢查可用記憶體。" width="1200" height="675" loading="lazy" />

不設定 `--threads` 即可使用自動調校，無需任何設定。seine 從它所知的最佳起點開始：先是這台機器儲存的結果，其次是針對你的 CPU 型號的起點，最後是依據核心數與可用記憶體得出的估計值。然後它以逐步增大的步幅搜尋，直到增加執行緒不再有幫助，再逐步縮小範圍。

在每個候選設定前後都執行目前設定，代表負載變化（例如瀏覽器分頁或背景更新）不會讓候選設定佔便宜或吃虧。明顯較慢的候選會被提前終止，所以大多數機器幾分鐘內就能完成。

## 儀表板上的 Tuning 列是什麼意思？

儀表板的 `Tuning:` 列顯示調校進行到哪一步：

| 列 | 含義 |
|---|---|
| `trying kernels, about 4 min left` | 一邊挖礦一邊比較 CPU 運算核心程式 |
| `12 vs 16 threads, about 3 min left` | 正在比較兩個執行緒數；測量期間執行緒數在兩者之間切換 |
| `update: 12 vs 14 threads, ~2 min` | 新版本對你的 CPU 做了變更，只測試變更的部分 |
| `done` | 調校完成。除非情況發生變化，執行緒數保持不變 |
| `low on RAM, best is 12 threads` | 減少執行緒執行，直到記憶體再次空閒 |

日誌會在調校開始時寫一行說明原因，結束時再寫一行，例如 `tuned to 12 threads`。[儀表板指南](/zh-hant/blog/seine-dashboard-explained/)說明了其他面板。

## 為什麼 seine 使用的執行緒比它能用的少？

每個 CPU 執行緒佔用一大塊記憶體區域，所有執行緒共享機器的記憶體頻寬。超過一定數量後，增加執行緒不會提高算力，反而會佔用其他程式可以使用的記憶體。因此，seine 把所有與最快速度相同的執行緒數都視為同樣好，並保留其中最少的一個。你得到同樣的算力，同時留出更多空閒記憶體。

這就是為什麼最佳執行緒數常常低於核心數或執行緒總數，而且看起來相似的機器之間也會不同。執行緒數、記憶體通道與記憶體分頁配置都會產生影響，所以另一台電腦的結果只能作為參考，不能直接照搬。[記憶體指南](/zh-hant/blog/how-much-ram-to-mine-blocknet/)說明了每個執行緒的記憶體需求。

如果你更重視節省電力與記憶體，而不是最後那一點算力，`--cpu-profile efficiency` 會保留一個接近最快速度的較少執行緒數。

## seine 也會調校 CPU 運算核心程式嗎？

會。這裡的運算核心程式是指針對某一組處理器指令實作雜湊演算法的軟體程式碼。seine 會檢查你的 CPU 支援哪些指令，絕不嘗試無法執行的運算核心程式，並略過在你的 CPU 上不佔優勢的運算核心程式。其餘的會在挖礦時比較，然後再決定執行緒數。運算核心程式的切換發生在完整的雜湊之間，所以挖礦不會中斷，礦池連線也保持不變。

## seine 什麼時候會重新調校？

Tuning 列顯示 `done` 後，seine 不再進行定期測試。只有當情況發生變化時，它才會重新檢查：

- **新版本對你的 CPU 做了變更。** 新版本從你儲存的結果開始，只測試變更的部分，例如新的或改進的運算核心程式。沒有變更雜湊計算的版本完全不做測試。
- **算力持續一段時間發生變化，** 例如另一個程式開始或停止大量使用 CPU。
- **先前因記憶體不足限制了執行緒數，之後有更多記憶體空閒。**
- **硬體、作業系統或 CPU 限制發生變化，** 例如容器的 CPU 限制。

每種情況都會在日誌中寫一行，說明調校開始的原因。自動更新會保留你的調校結果，所以更新 seine 不會讓調校從頭開始。[更新指南](/zh-hant/blog/update-seine-miner/)說明了更新的運作方式。

## 其他程式需要記憶體時會怎樣？

seine 每秒檢查一次可用記憶體。當其他程式需要記憶體時，CPU 執行緒會算完目前的雜湊，然後暫停並釋放各自的記憶體區域，Tuning 列顯示 `low on RAM`。記憶體再次空閒後，執行緒會恢復。它學到的最佳執行緒數仍然儲存著，所以短暫的記憶體緊張不會抹掉它。

在 Linux 上，釋放的顯式 HugeTLB 記憶體區域會回到預留的大分頁記憶體池；seine 不會調整該記憶體池的大小。[大分頁指南](/zh-hant/blog/huge-pages-blocknet-mining/)說明了如何預留大分頁。

## 儲存的調校結果如何重複使用？

結果儲存在資料目錄（預設為 `seine-data`）中的 `seine.cpu-autotune.json`。下次啟動時，seine 會直接恢復儲存的結果，Tuning 列顯示 `done`。如果算力與上次明顯不同，它會重新調校，並在日誌中說明原因。請在多次執行之間保持同一個資料目錄，讓 seine 能找到這個檔案，並讓每台礦機產生自己的檔案：複製另一台機器的檔案沒有幫助，因為結果取決於具體的硬體與設定。

## 可以自己修改執行緒數嗎？

可以。在儀表板中按 `-` 或 `+` 可以減少或增加一個 CPU 執行緒。調校顯示 `done` 後，修改會立即作用於正在執行的執行緒，GPU 與礦池連線繼續運作。調校仍在選擇執行緒數時，按鍵會等待，儀表板會顯示調校還剩多少時間。按鍵調整只對本次執行有效；下次啟動會再次使用儲存的結果。

要從一開始就固定執行緒數，使用 `--threads`，例如 `--threads 4`。seine 會保持該執行緒數，同時仍為它選擇最佳運算核心程式。`--disable-cpu-autotune-threads` 會完全關閉執行緒與運算核心程式的調校。[參數參考](https://github.com/zpalmtree/seine/blob/v0.3.1/docs/MINER_FLAGS.md)記錄了這些選項，[邊用電腦邊挖礦](/zh-hant/blog/mine-while-using-pc/)說明了如何在使用桌上型電腦的同時挖礦。

日常挖礦請從預設設定開始，讓調校達到 `done`。用 CPU 裝置列追蹤調校試驗，用[礦池統計](https://bntpool.com/blog/zh-hant/track-your-miner-on-bntpool/)追蹤已計入的挖礦活動。
